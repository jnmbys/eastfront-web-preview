## 唯一策略改动

`ai/fair/attackReserve.ts` 仅检查当前德军移动阶段、起点邻接已识别敌人的本方未移动单位。以当次PlayerView构造静态战斗候选，拟移动后只改变该单位公开位置和hasMoved，冻结其余已授权观测。前后使用已有单兵/最多四单位组合、原攻击评分及门槛；不比较MOVE分与ATTACK分，不使用Core合法性、隐藏单位、未来状态/骰点。

前有达标组合、后无达标组合且该目标候选族完整时，过滤该移动并继续**原排名**。组合减少、最高分降低但仍有达标组合不触发。每次策略调用重新建立保护，无跨动作/回合锁定。邻敌移动仍须满足017原风险/公开ZOC/途经停步/路线预算；014推进保护与拒绝上限未改。

`candidates.ts` 只增加完整性元数据：计算该可见目标在现有候选族内应有的单兵及2–4人组合数量，与实际输出数量比对；不增加枚举。后候选截断，或己方攻击资格字段未知，均不能证明“组合全消失”，因此不以此过滤。已存在正评分后组合即足以放行，无需把不完整误称完整。候选上限128、附加组合上限64、原移动单元/决策/路径预算768/32768/16全保留。完整是相对既有直攻族，不是声称穷尽支援/外方授权或所有Core合法打法。

`basicAgent.ts` 只在原排名得到完整MOVE前缀后调用保护；攻击评分、同分随机序、拒绝历史处理均未改。新增位置评估会产生原视图没有的达标组合，不只机械删除旧候选中的移动单位。Core只作为既有Host/离线回放裁判，不进入策略接口。
