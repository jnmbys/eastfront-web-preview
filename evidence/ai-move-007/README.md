## Core限制、AI主动停步和候选截断分开

离线对4个前锋的6个邻格共24个单步提案调用原 `validateMoveAction`，不提交Action、不改变状态/RNG。每单位5个邻格被 `ENEMY_OCCUPIED_HEX` 或 `ENEMY_ZOC_TO_ZOC` 拒绝，仅表中后退出口合法。特别是18的部分ZOC原因来自权威裁决，不能拿来推断策略已知那些隐藏敌军。逐格issues和MP见before.json。

原Core契约 `vendor/eastfront-digital-core/dist/rules/movement.js`：普通单位不能直接敌ZOC→敌ZOC；可以离开ZOC到非敌ZOC；进入敌ZOC通常结束移动。进入ZOC强制停步、两ZOC间禁止移动，与AI的“本来已邻敌就完全不给MOVE分数”不是同一规则。这里没有UNIT_ALREADY_MOVED或MP不足导致前锋首步不动。

`ai/fair/routing.ts` 明确保留R1的已识别相邻停步；已识别敌军存在时，路线目标集合本身也是敌军邻格。该分支是保守接敌策略，不能冒称Core彻底锁死这些单位。两点也都确有可见敌军，不支持“目标消失后仍保留旧目标”的解释。

为区分候选截断是否在本节点导致不动，另在**同两个保存的FairInput**上做临时诊断：仅将被截去的6条PZ-04提案追加回候选，保留原候选及其索引。两点追加项全部实际命中邻敌停步分支，最终选择仍与原trace一致，输入未被修改。该结果是反事实诊断，不能替代上表的原执行分支；也不是已修复候选。见 `capped-front-check.json`。

## 决定与边界

**本轮不修改AI。** 在这两个检查点，没有证据表明资格状态被错误判断，或正常前向单步被Core误拒绝；仅补回前锋候选也不改变选择。已知合法出口均暂时增加首都距离。解除邻敌停步并调整已达成的接敌目标，会引入新的脱离接敌/后撤绕行决策，不能把它包装成已获证据支持的最小候选补漏。

这不证明保守策略最优，也不证明预算内不存在先后退再前进的多格路径；本轮未搜索该反事实路径，未核验整个回合的所有合法路径，也不把两个点外推到全部持平回合。候选上限对其他单位、其他节点的影响未知。若研究聊天要继续，一个可验证假设是：在允许短暂后退且保留当前风险约束时，部分前锋能找到预算内净推进路线；须另立明确的脱离接敌目标/风险条件，再决定是否改策略。本轮没有实施或验证该假设。
