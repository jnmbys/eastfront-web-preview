## 需要明确的最小接口决策

若下一步仍要求共同中间目标驱动**新多格路线**，建议先明确允许：让Host与策略按同一个、仅基于授权信息的计划快照生成候选，并对这个窄接口做版本化、开关、作用域和回放测试。具体待定的是谁持有计划快照、Host如何获得同一快照以及目标失效后两端如何同步；不是建议放开任意MOVE、接入Core oracle或暴露隐藏状态。

保持接口完全不变的替代是：只在原候选菜单内做共享目标评分/选择，承认部分目标导向路线不可提交；或者缩成单步MOVE。但前者不等价于完整目标驱动寻路，后者改变每回合MP利用，会混入额外变量。本轮均未实施，未选参与单位规则/区域策略/解除规则，不自动叠加另一方案。

因此本轮尚未达到“定向验证通过后冻结候选、跑两局”的条件。计划按对局/座位隔离、隐藏信息成对一致、解除恢复、集合等待上限及计划搜索开销这些**策略验收项仍未完成**；不能把单节点Host检查包装成这些项目通过。不存在主攻组进展/最终胜负或采纳建议数据。采纳状态为未测试，014保持不变。
