## SP维护优先与预留

首版采用保守、易审计方案：在E5同一私有结算输入上先运行原完整SP求解（原progressive维护优先级及后续储备目标都保留），证明精确可行并完成原约束审计，冻结双方全部SP流、逐单位配送、source/hub余额及维护/欠账/耗损结果。然后只用真实剩余行容量运材料：

`当次SP行占用 + 其他有效预留 + 已提交货物占用 + 本次载荷 ≤ 原行上限`。

每个单位`paid=min(B,原库存+本次SP配送)`，`net=max(0,paid-min(B,原库存))`。逐单位paid/net与无材料参考解相同；有现存库存支付维护，不意味着又需要等额净配送，也不假定全军维护可全部满足。此冻结还保护了SP储备补充，**比仅保护维护更严格**；可能存在重优化后能运材料、而本方案仍运0的情况。本轮接受这种保守结果，不另开多目标联合优化。

历史账本停在L3/E4；T5保存的历史流量或004的其他路线流量均不能当作L4/E5剩余。必须从同快照的真实SP弧流重新汇总各行，再减已占/预留；保持所有未触及约束和守恒有效，不只验四个数字。若任一资源不足，材料0套、原合法SP计划照常结算。求解失败、超时、未知路径或缺失审计不是“0套成功”：整次边界拒绝/回滚。源短缺仍保留，不调配参数造余量。

预留必须在同一所有者锁内，原子锁住整套源库存、完整接收仓容及四项容量。只读报价不预留；同预留重试不能再次扣容量。提交时hold→used一次，不把同一hold同时算在两栏；私有失败只释放本请求hold，源库存/游戏/epoch保持原状。提交后回执丢失只重放凭证，不能释放已用容量或返还源库存。原3秒总预算覆盖该边界，不能给参考求解/材料步骤各加3秒；008须复用已求得SP计划，不能再无预算地调用旧settle重求一遍。
