## 当前结论

关闭判定已修正并验证。真实桌面浏览器在本机 TLS 阶段遇到 **`net::ERR_CERT_AUTHORITY_INVALID`**，未能进入登录。因此登录、浏览器自动 cookie、对照启动、连续前台五秒、移动、JSON 下载和文本备份均未完成本轮真实浏览器验收。

依照用户“上述通过后”才能发布的条件，本轮**没有启动公网隧道，没有交付华为盲测链接，也没有新真机记录**。一次临时预览授权仍以真实桌面预检通过为前提；没有将 Node 手工承接 cookie、组件测试或旧 MP013 结果替代浏览器通过。

## 关闭判定修订

原 MP013 `stop.ps1` 将 `httpStatus=null` 也纳入关闭成功；curl 超时、DNS/TLS 错误等可触发这个值。新版本独立放在 `scripts/mp014/`，原 MP013 脚本、清单、文档和证据最终与基线逐字节一致。

新报告使用 `closure-mp014.json`，与旧 `closure.json` 分开，不覆盖历史记录：

| 维度 | 记录与成功条件 |
| --- | --- |
| 进程 | 每个 PID 独立记录 EXITED、ALREADY_EXITED、IDENTITY_MISMATCH、STILL_RUNNING 或 UNKNOWN；检查创建时间与脚本身份，不误杀复用 PID。观察或停止失败仍写证据。 |
| 本地监听 | CLOSED、LISTENING 或 UNKNOWN；查询失败不等于无监听。与进程退出各自保留。 |
| 公网探测 | 保留 curl exitCode、有效 HTTP 状态和耗时。超时、DNS/TLS/连接错误、空响应、000、探测中断统一 UNKNOWN。即使中断前收到 502，探测仍为 UNKNOWN。 |
| 未启公网 | NOT_ATTEMPTED，`publicUnavailableVerified=false`，整体只能 LOCAL_ONLY_VERIFIED。 |
| 收到 HTTP | 5xx 标为 HTTP_UNAVAILABLE，只证明这次请求收到不可用响应；其余标 HTTP_RESPONDING。必须同时确认进程退出、本地端口关闭，才能称 VERIFIED_AT_PROBE。5xx 不是永久失效、DNS 删除或根因证实。 |

本地已经关闭但公网 UNKNOWN 时，整体为 PUBLIC_NOT_VERIFIED，关闭命令报“未完全验证”，不会声称公网失效已验证。这个区分不改变运行期间“任何异常 500 或认证异常留证并关闭”的要求。

[19 项分类检查](../evidence/mp-014/closure-policy-tests.json) 覆盖 timeout、DNS、TLS 握手/证书失败、connect、空/000、收到响应后超时、HTTP 500/502、登录重定向、403/200、进程/监听未知或未退出，以及纯本地关闭。

[停止脚本集成检查](../evidence/mp-014/stop-timeout-fixture.json) 使用仅在测试进程内生效的 curl 超时替身，确认**真实 stop.ps1** 在本地已关闭时仍写出公网 UNKNOWN，并返回未完全验证。这份记录的 `publicOpened=true` 是人工输入，不代表曾发布或真实探测了公网。

[实际本地生命周期检查](../evidence/mp-014/lifecycle.json)：新启动器加载原认证边界、原覆盖层、原夹具；三个监听均为回环，匿名配置请求返回登录重定向；随后实际进程退出、端口关闭，重复停止通过。测试口令随机生成，仅在内存，不用于用户验收、不进入命令行或证据。

## 真实浏览器阻塞证据

[desktop-preflight.json](../evidence/mp-014/desktop-preflight.json) 记录了 Codex 内置桌面浏览器对 `https://localhost:4193` 的实际导航拒绝。该本机 TLS 探针使用原 MP013 一天有效、自签且含 localhost / 127.0.0.1 SAN 的测试证书，只提供 TLS 预检，无游戏、登录或 cookie 接口。没有绕过浏览器警告、关闭证书验证、注入 cookie，或修改系统信任。

只读检查 CurrentUser/My 和 LocalMachine/My 共四张证书，未发现 localhost SAN 的可用证书；在相关根存储中也未找到 MP013/localhost 测试信任。这个检查不声称穷尽所有自定义浏览器证书来源。Edge 自动控制清单另外报告 `nodeRepl.fetch request failed`，没有把该工具连接失败误算作游戏启动故障。内置浏览器的证书拒绝是本轮已直接观测到的阻塞。

TLS 探针结束时输入管道已关闭，按已核实的单一进程身份停止并确认 4193 无监听；未回收的进程内请求计数记为 null，不将缺日志当作请求未到达的证明。后续给探针补了 60 秒自动关闭上限；这不改变证书信任或验证行为。

继续本机验收需要提供浏览器信任的 localhost 服务端证书，或另行明确授权安装、验证后移除本机测试证书信任。当前授权中的临时公网方案不自动包含修改系统证书信任；本轮没有执行该改动，也不会以提前发布公网来跳过本机前置检查。
