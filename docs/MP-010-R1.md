## 分类口径

离线 `summarize.mjs` 和网页正常样本计数共用 `web/classify.mjs`。每条记录仅进入一个主分类，但保存全部原因；例如“RESYNC 且缺 ACK”进入异常组，同时保留 missing-ack、missing-exact-result 等未完成原因。优先级为无效 → 异常 → 未完成 → 暖机/检查 → 正常；暖机或检查中发生恢复也进入异常桶，原记录的 check 用途不变。

| 分类 | 条件 | 是否占正常 10 次 / 正常指标统计 |
| --- | --- | --- |
| normal 正常完成 | 匹配构建/格式；明确 RESYNC=0；单次提交；有效 ACK；acceptedRevision 与实际 appliedRevision 精确一致；有效 appliedSequence；同版本恢复可操作且结束时仍可操作；提交前已连续前台等待 5000ms；无异常事件 | 是；人工可见反馈另计判读数 |
| abnormal 异常 | RESYNC、拒绝、断网/前后台事件、非单次提交或人工报告问题 | 否；单独保留统计和原始记录 |
| incomplete 未完成 | 缺 ACK、缺精确结果、未恢复可操作、缺恢复计数或缺前台等待证据 | 否；单独保留现有指标，缺失值为 null |
| warmup 暖机 | 完整无异常，且明确选择暖机用途 | 否；异常暖机另入异常/未完成桶，用途与指标保留 |
| check 检查 | 完整无异常的专门检查用途 | 否；恢复或未完成检查另入对应桶，原用途保留 |
| excluded 无效 | 构建/格式不符或人工标为无效 | 否；原始记录和指标仍保留 |

schema 为 `MP010-descriptive-v2`。各桶保留 `records[].row` 原记录、sourceIndex、reasonCounts、指标 n/min/median/max；输入文件不改写。null、缺字段、NaN、Infinity、负数、数字字符串不当作 0。真实数字 0 可以被统计。没有稳定 P95 或网络延迟降低结论。异常桶指标只是描述已观察到的数值，不能把其分类原因缺失的 ACK/关联自动解释为可信完成。

`Trial.result()` 新增 appliedRevision / interactiveRevision，只在原有精确 ACK 关联实际应用/可操作时导出；仍保留 snapshot 先到、ACK 后到的实际时间。没有延迟授权 snapshot 应用。

## 修订操作卡

1. 打开验收入口，填设备、系统/浏览器、固定网络，选择部署或移动、real 或 delay；两版使用同一个服务实例与场景。打开录屏。默认用途是**暖机**，A/B 各完成并保存一次。
2. 切换为**探索性采样**。每次“开始下一次”后，自动准备目标，再等待页面提示“连续前台等待 5 秒已完成”；此时点游戏内确认。提前点击会被验收包装拦截，切后台或目标变为不可确认会重新等待完整 5 秒。五秒不计入输入后的反馈/完成耗时。
3. 等待正式结果并可操作后结束、保存。页面按正常完成数显示 A/B 各 10 次进度；暖机/异常/未完成均不占配额。通常按 A B B A 交替，某版本达到 10 次后优先补另一个版本。每个场景/条件单独采样。
4. 分别选检查用途完成重复点击、拖动缩放、断网恢复、前后台切换；timeout 仍只做恢复检查。导出 JSON；下载不成功时复制页面中的完整 JSON。首次可见反馈从视频判读，rAF 只作帧机会代理。保留原件，在副本补录视频值。

`preparation` 记录提交时连续前台等待值及是否达标。门槛由两版同一份包装脚本实现，原编译客户端模块不变。暖机目的与正常采样是独立计数，不再靠“标成无效”替代暖机入口。五秒只验证目标可确认和页面前台，不能保证操作系统已完全空闲或网络没有背景流量。

方案是“现有本机 + Cloudflare Quick Tunnel + 本人访问边界”。无需购买域名：下一轮获批后启动 Quick Tunnel，它会直接分配真实 `https://随机名称.trycloudflare.com` 地址并提供边缘 HTTPS，复制输出地址作为 MP010_ORIGIN；本轮未启动隧道，因此不存在可以提前给出的真实预览 URL。地址取得方式是服务实际分配，不是等待管理员填占位域名。[官方 Quick Tunnel 操作及限制](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

访问范围只限用户本人：隧道**只能指向 4181**，不能直接指向无认证的 4180。`owner-preview.mjs` 提供本次临时口令登录；用户在自己电脑交互输入一条密码管理器生成的至少 24 字符随机口令，仅自己持有。口令不放 URL、不写 Git、不写采样表或日志。登录成功产生内存会话与 Secure / HttpOnly / SameSite=Strict cookie，最长 8 小时、最多 4 个会话，允许本人两台设备；停止访问边界即全部失效。HTTP 与 WS 均校验登录，匿名 WS 拒绝，凭据在转发给验收网关前移除。此边界是单拥有者持有秘密的访问控制，不提供多人账号或第三方身份实名保证；不得转发口令。

以下为下一轮获批后操作员实际执行的配置，**本轮未执行**：

1. 从 [Cloudflare 官方下载页](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/) 获取 Windows amd64 `cloudflared.exe`，放到本机 `.mp010-build/tools/`，记录其版本与 SHA256。本机当前 PATH 未找到 cloudflared，默认目录没有已有 tunnel YAML；不依赖新云主机、DNS 权限或 Render 付费实例。
2. 校验本准备提交及 R1 产物。先保持 4181 没有服务，在终端 1 执行：

```powershell
.\.mp010-build\tools\cloudflared.exe tunnel --url http://127.0.0.1:4181
```

此时域名已分配但后端尚未运行，只会连接失败。复制终端输出的真实 HTTPS origin，不手写主机名、不启用 Windows 后台自启动、不改防火墙入站规则。

3. 终端 2 在本 checkout 中启动固定验收服务：

```powershell
$env:MP010_ORIGIN = Read-Host '粘贴刚分配的完整 https://...trycloudflare.com 地址（无末尾斜杠）'
$env:MP010_HOST = '127.0.0.1'
$env:MP010_PORT = '4180'
$env:MP010_BEHIND_TLS = '1'
node scripts/mp010/serve.mjs
```

4. 终端 3 输入相同真实 origin 与本人随机口令，启动访问边界：

```powershell
$env:MP010_ORIGIN = Read-Host '粘贴同一个真实 HTTPS origin'
$mp010Secret = Read-Host '本次至少24字符随机口令；仅本人持有' -AsSecureString
$mp010Ptr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($mp010Secret)
try {
  $mp010Plain = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($mp010Ptr)
  if ($mp010Plain.Length -lt 24) { throw '口令不足24字符' }
  $mp010Bytes = [Text.Encoding]::UTF8.GetBytes($mp010Plain)
  $env:MP010_OWNER_PASSWORD_SHA256 = [Convert]::ToHexString([Security.Cryptography.SHA256]::HashData($mp010Bytes)).ToLower()
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($mp010Ptr)
  $mp010Plain = $null
  if ($mp010Bytes) { [Array]::Clear($mp010Bytes,0,$mp010Bytes.Length) }
  $mp010Secret.Dispose()
}
try { node scripts/mp010/owner-preview.mjs }
finally { Remove-Item Env:MP010_OWNER_PASSWORD_SHA256 -ErrorAction SilentlyContinue }
```

这些交互命令按 PowerShell 7 / 当前本机环境编写，不把口令写入命令历史。先用未登录浏览器确认只能看到登录页、无法读取构建文件或升级 WS，再由本人在 iPad Safari / 华为浏览器登录，核对 SHA 后暖机和采样。TLS、Cloudflare 实际链路及平板登录/WS 仍是下一轮发布后的验收门槛；失败就关闭预览，不能绕过认证降级为裸隧道。若所在地网络无法稳定访问 trycloudflare，则本方案受阻，不自动改用生产主机。

增量云费用预算 **0**：现有电脑、临时免费 Tunnel、临时域名/HTTPS，不开新 Render 服务或付费 Access/DNS 资源；原有 Render 账单不变。电脑耗电与现有网络流量未计价，不保证其成本为零。免费临时 Tunnel 无 SLA、最多 200 个同时进行的请求、域名每次重启变化；这会影响网络实验的外推范围，两版必须走同一个地址、同一个运行批次。[Cloudflare 免费 Quick Tunnel 说明](https://developers.cloudflare.com/changelog/post/2026-03-19-wrangler-tunnel-commands/)。Tunnel 支持 WS，但本机至边缘与两台真机的实际兼容性尚未测试。[官方 WebSocket 支持说明](https://developers.cloudflare.com/cloudflare-one/faq/cloudflare-tunnels-faq/)

电脑测试期间需接电并保持运行，休眠/断网会中断预览；本轮未改电源设置。8 小时有效期限制新 HTTP/WS 请求，已经建立的 WS 在断开或停止边界进程时撤销，因此结束测试不能只等待 cookie 到期。

关闭方式：先本人导出 JSON/保存视频，再终端 1 Ctrl+C 停止 cloudflared（真实域名立即失去后端）→ 终端 3 Ctrl+C 清空访问会话 → 终端 2 Ctrl+C 停止验收服务和内存房间。检查 4180/4181 无监听、匿名/原登录页面都无法访问。无需删云资源、无需改生产 DNS。换包回退必须关闭整条链、核对旧包和对应脚本 SHA 后重新启动新临时地址；旧 MP-010 数据和 R1 数据不可混为同一正常组。
