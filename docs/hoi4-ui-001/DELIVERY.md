## 实际操作与检查

Codex内置浏览器、Windows桌面视口1568×980；第二席由独立协议访客保持连接，**不是双浏览器/真机验收**。

1. 创建新房间→进入德军地图→两席齐备→房主开始。
2. 左上“部队”→G-019→“移至友军格”→地图G-020。服务器接受，军团归属保留。
3. 继续1×；经40游戏分钟，G-019真实路段23%，仍在22,4，目的地23,4，剩余115游戏分钟。没有视觉瞬移。
4. “后勤”→显示补给地图；看到真实覆盖短缺和各枢纽占用。
5. “生产”→步兵线减一厂→火炮线加一厂。总军厂3不变，火炮2厂/效率20%/日产8件，空闲恢复0。不是前端伪预览。
6. 暂停→保存→刷新重连，06:40与生产分配保留。底部军官选择能打开六队名册及原战线操作，编制入口能打开原编辑器。

证据 evidence/hoi4-ui-001/：01总览、02命令、03补给、04生产、05军团、06编制截图，以及 ui-check.json / protocol.json。02/03记录过程状态，其余为收尾画面。界面截图不含邀请/身份凭证。

作者检查：两阵营所有面板渲染、关键控件唯一ID、名册仅己方、渲染不改权威状态/RNG/账本、工厂调整经原事务通过。为隔离同机Cookie增加服务选项（默认旧名称不变），复用受影响的独立身份/第三人/跨房间/越权/重试/迟到请求/断线暂停/真正进程重启恢复检查通过。没有改共享战斗、经济与AI算法，不重跑其专项。

采集小问题：第一次Node渲染检查缺matchMedia模拟，修正测试环境后通过；一次地图按钮匹配使用了文本而非可访问名未命中，检查真实DOM后用可见文本定位成功，没有盲点。
