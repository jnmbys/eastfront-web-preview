## 测量失误、补测与未通过范围

1. `baseline/`首轮完整记录保留：1×307.42秒、4×189.193秒，但单向拖动让镜头逐渐偏离战场。因此不以其绘制数据作最终判断，不将复测差异称为代码优化收益。
2. `fixed-camera/`长时间合成器追踪导出超过Node字符串上限，发生在持续阶段完成之后。通过本任务Node进程的临时loopback inspector，回收同两个仍打开页面的原记录及原动作/内存数组；未重建战役代替。`browser.json`保留`measurementErrors`。服务端数据已持续写盘。调试和两个测试进程已退出。
3. 全窗口rAF机会间隔p50/p95约3.1/3.2ms，1×最大59.3ms、4×43.8ms。**这是无头调度代理，不是实际屏幕绘帧，不能据此认证33ms绘帧目标。**
4. 补充同身份、同现场的短1×交互：实际合成器DrawFrame间隔德/苏分别n246/236，p50为3.353/3.437ms、p95为31.930/32.590ms、最大34.748/37.519ms。完整连续合成器证据仍缺失；没有把短测当作持续绘制通过。DroppedFrame事件原样保留，不换算成物理屏幕掉帧率。
5. 持续测量的精确“选中ID→标题”观察器被紧随其后的按钮点击清空，样本为0，不拿任意DOM变化冒充选中反馈。短补测明确等待所点永久ID出现在标题后再下令，每席5次；本地选中反馈p50/p95/最大为91.7/108.4/108.4ms与86.9/97.1/97.1ms。对应合法命令全部接受。原连续ACK样本仍真实，但不声称它证明每次快点都作用于刚点的那支单位。

测量工具已改为先等待目标标题、保留未完成观察目标，合成器仅采每阶段首轮手势、64MiB上限，导出错误单列且不阻止保存原记录。该收尾改动通过语法检查及上述短真实浏览器路径核验；没有再次跑第三套全窗口，也没有修改产品操作或权限。

**工程判断：**普通命令500ms目标、无反复>1秒主线程长任务及无队列失控在本机无头范围内得到支持；持续真实绘帧33ms、前台/后台差异、浏览器全进程内存和真机触屏仍未验收。没有证据支持现在改运行代码或调整服务器规格。
