## 3. 基地、接收点、入口与实际通路

现有Core有**恢复基地查询**，没有工业组建基地注册接口。德军恢复基地来自已修通的活跃铁路末端及其线上城市；苏军来自活跃独立来源及完整补给铁路上的城市。恢复单位只需在基地距离2以内，不要求站在基地格上，但还须受损、正常补给、本己方回合未移动/攻击/支援、无相邻活敌、RP足够且未超恢复额度。普通坐标标签不能代替这些检查。

本夹具开局Core查询：G恢复基地为空；S为D10、J6、M15、R10、V5、X14、AC10、AC11、AD10。T5合法修复A10—B10—C10后，G查询新增C10。这个变化由Core铁路状态推导，不是夹具写入基地名单。

J6/M15/R10/AD10在本状态是S恢复基地，所以相邻预留格可满足**恢复距离条件这一项**；不能写成预留格绝不可能恢复，也不能授予专门维修设施或工业收益。AD9在本夹具有2支苏军，其他三格为空，这些是部署后的事实，不是020永久占用规则。

“没有实体公路/铁路边”也不等于“没有任何补给末端通路”：原求解器的`road`图采用合法步兵通行成本，含非公路移动。我们只调用它的原`adjacency`过滤器提取连接证据，没有另写物流分配算法。四格没有装备接收者、库存或卸货接口；即使存在步行边，仍不能证明装备货运、跨格仓库服务或组建合法。

实际货流证据避免把连通性猜测当配送：

- 首次配送，G-I-01在C10收到8q=2 SP，原求解器记录的末段为`GH3(A16) → A15 → A14 → A13 → A12 → A11 → B10 → C10`，总成本8。此时G恢复基地仍为空，说明“收到补给”和“具备恢复基地资格”是不同条件。
- T5修路后，原求解器在`A10→B10`、`B10→C10`各记录32q=8 SP铁路货流。**G-I-01自己的4q到账仍来自GH3的上述末段**；不能把这个单位的补给误归为新铁路直接交付。
- 全部原始货流、逐源实用、枢纽变化、W/T/边/桥约束保存在[SETTLEMENTS.json.gz](SETTLEMENTS.json.gz)。[FACTS.json](FACTS.json)另列两个真实检查点的源→枢纽铁路连接见证；它仅证明图上连通，不是工业共享容量预留凭证。

空部署导入的640格`control`均为null，后续保留Core实际更新；没有按东西位置补己控或homeSide。现行物流和原增援使用各自现有占据/ZOC/铁路规则，不等于candidate.1工业入口所需的己控授权已解决。
