## 延迟链与显示状态

```text
点击确认 → 原有提交门禁 → 保存本机意图 → 原有 Client Send
                         └→ 状态文案与独立 SVG 标记 → 首次 rAF 回调
Client Send → Server Receive → 校验与 Core Apply → ACTION_ACCEPTED
            → Snapshot Build / Encode / Serialize → Network Send
            → Client Receive / Decode → 应用授权 snapshot → UI 更新 / 必要投影 Query
```

| 事件 | 显示与行为 |
| --- | --- |
| 原提交入口产生 requestId | “正在提交”；复制本人部署目标或普通移动路径，不修改权威模型；重复点击仍被原门禁阻止 |
| 对应 ACTION_ACCEPTED | “已接受，正在同步”；不提前移动棋子、扣 MP、放置单位或更新 FOW |
| 与 acceptedRevision 对应的授权 snapshot 应用 | 更新正式模型并清除标记；普通移动可能仍需原有新 revision 投影 Query 才恢复控件 |
| 对应拒绝 | 清除标记，按错误代码显示安全的本地化原因；不转述隐藏单位、阻挡或内部规则细节 |
| 超时或断线 | 清除失效几何标记，显示“结果待确认 / 正在重新同步”；复用原恢复流程，不把未知结果当失败重发 |
| 重同步 snapshot、离开对局、权限或视角或阶段变化、移动单位不再属于当前授权视图 | 清除过期意图；重同步成功后恢复当前授权状态 |

关联同时使用当前 match、requestId、提交前 matchRevision、serverSequence 和 ACK 的 acceptedRevision。原有连续序号检查不变，真正的丢帧或乱序仍进入原重同步流程。

合法的 snapshot 先于 ACK 时，snapshot 仍立即更新权威视图。普通 snapshot 没有对应 action requestId，因此客户端不会仅凭位置相同或 revision 增大猜测成功：暂存已应用 revision，等待匹配 ACK 完成身份关联。晚到 ACK 若指向已应用版本，直接清除意图，绝不重新显示“正在同步”。无关 ACK、无关错误、同 revision snapshot，以及不匹配结果版本的较新 snapshot 都不能误清当前意图。收到重同步 snapshot 时以恢复完成收尾。

## 实现边界

待确认层只使用本玩家通过既有入口提交的坐标、当前授权己方单位起点和本地化文案。“待确认意图”虚线不表示路线已获批准，不做隐藏阻挡或隐藏敌军推断。图层 `pointer-events=none`，不创建正式 counter、单位命中目标或新的查询来源；等待期间保留拖动和缩放。

MP-009 相对上述开发基线没有修改 Core、规则、服务器、协议、snapshot codec、FOW 或几何模块。新状态不进入 QueryDraft、PlayerView、正式模型或网络消息。另一真实 WebSocket 玩家没有本方待确认意图；现有服务没有新增旁观者协议角色。

| 浏览器观察 | 结果 |

## 分段耗时

使用同一浏览器单调时钟关联 requestId。点击输入来自捕获阶段的 click 监听；反馈使用 SVG 已挂载后的首次 `requestAnimationFrame` 回调，**它是首帧机会代理，不是屏幕像素完成呈现的精确测量**。snapshot-applied 表示授权模型应用完成；其后的 UI 重建和必要 Query 不计入这一项。事件不携带 token、单位数据、坐标或 snapshot 内容。

| 本地单次样本 | 输入到反馈帧代理 | 提交到 ACK | 提交到授权 snapshot 应用 |
| --- | ---: | ---: | ---: |
| 部署 | 64.7 ms | 1823.9 ms | 4529.1 ms |
| 普通移动 | 5.6 ms | 1818.1 ms | 4520.6 ms |

ACK 人为延迟 1800 ms，snapshot 人为延迟 4500 ms；两次超时样本将 snapshot 延迟设为 12000 ms。原实现诊断依赖 UI 意图，清理后无法关联恢复结果，故旧样本耗时为 null。另一个缺陷是仅凭较新 revision 就记录当前请求完成；R1 已将诊断独立并要求匹配 ACK 与实际应用的 acceptedRevision。上表两个样本各自存在对应 ACK 和同 revision 应用记录，但原诊断不能推广为交错安全保证；旧事件不被回填或改写。[原始事件](../evidence/mp-009/browser-timing.json)、[计算结果](../evidence/mp-009/timing-summary.json)。这些单次样本不用于均值、P95 或收益百分比结论。

## 已知限制与验收建议

1. **iPad Safari 与华为真机待验收**：两台实际设备分别做部署、普通移动、连续重复点击、拖动缩放、断网恢复和前后台切换。需观察文字与虚线是否在下一可见帧出现、是否遮挡、是否残留，并采集足够样本后再讨论分位耗时。此次没有真机录屏或真实无线网络结论。
2. 首帧代理受主线程、设备负载及后台节流影响；SVG 标记随地图缩放，缩小到全图时标签较小，需真机验证可读性。
3. snapshot 先到但对应 ACK 尚未到时，权威棋子可已更新，意图仍保守等待关联；ACK 到来或超时恢复后收尾。协议没有新增用于提前归因的字段。
4. 仍保持一次提交的门禁，不能提前连续走棋。现有 Query/服务处理/网络传输成本不因显示提示而消失。
5. 三项冻结测试仍未通过，R1 已列清历史差异及 MP-009 新增差异；未授权更新冻结清单。局部 snapshot、分级同步及 Delta 继续暂缓。
