## 付款与归属的具体接缝

支付来源固定为013完整根的`industry.budget.freeI`，并绑定配置中原012永久grantId。目标为新**用途分账**`EASTFRONT-012-ISOLATED/RC009/E8-G-I-01/CARE-I`，不是新增拨款、不是原人员账户。一个根事务同时写：原freeI **5→4**、原累计`careTransferOutI` **0→1**、用途分账receivedI **0→1**且spentI **0→1**、唯一照管展期回执。用途分账可用余额为0。

- 原012来源守恒：`10 = free4 + productionSpent3 + handoffSpent2 + escrow0 + careTransferOut1`。
- 用途分账守恒：`transferIn1 = spent1 + available0`。合并看仍是10，不能再把transferIn当新收入。
- 原人员账保持`granted2 = acceptanceCareSpent1 + carriageSpent1`，available/escrow仍0。旧2I和旧4LQ均不可二次支付。

批准须明确允许原“装备生产用途I”转作这一笔人员展期。仅有余额不代表用途已获准。激活只允许T8德军恢复窗口、当前根/版本一致、原包REAR_AVAILABLE且未过期；不能先让013在E8隔离P再补付款复活。新回执覆盖这个永久包在源仓、在途和前线的同一延长期，013历史E7接收与E8原期限记录原样保留；后续有效期限查询必须识别这张新回执，而非重复初始化013。

激活事务失败：付款、转账、回执和有效期限全部还原。激活成功后**1I不退**：即使未能发运、被拒收、没恢复或提前终局，已购买这段有限照管/预留；不能按结果重新开免费预算。E8边界后来失败不撤销此前已成功激活的1I；只回滚失败边界自己的游戏/SP/货物/容量/回执。
