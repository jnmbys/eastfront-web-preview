## 同条件与测量口径

两版本使用同一个验收主机、相同服务端构建、相同场景准备和真实 WebSocket；相同场景/条件接入相同服务实例，不使用生产房间。两台设备分开采集，固定同一 Wi-Fi 或固定热点、位置、方向、缩放、动画设置与省电状态；一次只跑一个样本，停止下载等后台负载。网络瞬时抖动无法保证相同，使用 A B B A 交替减少时间顺序偏差，并保留所有异常。

| 条件 | 夹具行为 | 用途 |
| --- | --- | --- |
| real | 不注入延迟；真实设备到验收主机网络 | 主采样组，仍是固定测试场景和陪练，并非生产在线对局 |
| delay | ACK 至少 1800 ms；其后的有序 snapshot 至少 4500 ms | 观察等待反馈；与 real 单独分析 |
| timeout | ACK 至少 1800 ms；snapshot 至少 12000 ms | 仅恢复检查，不计入 10 次正常采样 |

延迟从夹具收到服务端 ACK 的时刻算起，不是从用户输入开始。夹具使用 FIFO，保留真实 serverSequence，不能重标序号或忽略失序。网络、CPU、压缩与渲染仍会额外增加耗时，因此 4500 ms 不等于观测总耗时精确为 4500 ms。压缩协商结果另行记录；不同协商结果不混组。

两版使用同一份 `scripts/mp010/web/measure.mjs` 与 `bootstrap.mjs`，不依赖只有候选才有的 pending/ACK 诊断事件。默认不开原 `transportDiagnostics` 浮层，避免给对照额外即时反馈。观察器只包装既有提交和接收回调，原方法、参数、返回值与异常均保留；不修改 Core、正式模型、协议、权威判断和恢复检查。

| 导出字段 | 定义 |
| --- | --- |
| `sendMs` | 确认 click 捕获到原发送入口之前；同 iframe 单调时钟 |
| `ackMs` | 确认 click 到匹配 requestId 的有效 ACK 接收处理返回 |
| `authorizedAppliedMs` | 确认 click 到授权模型已赋值、同步 UI 回调开始前；必须与匹配 ACK 的精确 acceptedRevision 关联 |
| `interactiveMs` | 确认 click 到该结果版本第一次再次 `session.interactive=true`，包括必要投影 Query 的等待 |
| `feedbackFrameOpportunityMs` | 前台 rAF 回调第一次观察到状态文字变化、待确认层或授权结果；**只是帧机会代理，不是像素实际显示时刻** |
| `visibleFeedbackMs` | 人工录屏逐帧判读输入释放到游戏首次可见回应；未判读为 null，绝不由 rAF 自动补入 |

snapshot 先于 ACK 时，观察器先保存实际应用/可操作时间，ACK 晚到再关联，不能用 ACK 时间替代。缺精确版本、缺 ACK、拒绝、恢复、断网或切后台必须单列；不能以 0 替代缺失时间。自动 T0 是 JavaScript click 捕获，不包含硬件触摸到事件派发的延迟；人工视频 T0 是可辨识的确认释放，两种口径不相减计算“网络成本”。

## 用户操作卡

1. 用目标浏览器打开获批的 HTTPS 验收链接，填写设备、系统/浏览器版本，选择固定网络、场景和条件。设备机型可写入版本栏，不写姓名、账号、SSID 或凭据。先各做 A/B 一次暖机并单独标为无效；开始录屏或外部拍屏，保持同样设置。
2. 点“开始下一次”，自动建房、选座、准备目标。目标就绪后，两版都等待相同的 5 秒并确认地图加载结束，再点游戏内确认。除检查组外，每次只提交一次，不另选目标。等待正式结果和再次可操作，点“结束本次并记录” → “保存本次”。
3. 该场景该条件完成 20 次，A/B 各 10 次；切换另一场景继续。结束后导出 JSON，保留录屏片段编号。下载未成功时，复制页面显示的完整 JSON 保存为文件。首次可见耗时可当场填，也可在导出的副本中补录，原始 JSON 留存。

每台设备的 real 组为部署 A10/B10、移动 A10/B10，共 40 个正常样本；delay 组另做相同 40 个样本，不能混算。暖机、重复点击、拖动缩放、断网、前后台和 timeout 均另列。记录中的匿名 `deviceRunId` 标识当前浏览器采样存储，不是硬件指纹；版本 SHA、夹具摘要、设备版本、网络条件、场景、轮次、时间和视口绑定每条记录。

录屏无法看出点击时刻时用外部拍屏或可见触点指示；不要用后来出现的提交文案反推输入时刻。记录视频帧率及第一个回应类型，按“相差帧数 × 1000 / FPS”计算；精度受至少约一至两个视频帧及录制丢帧影响。无从判读则保持 null。正式位置、MP、部署计数是否提前变化以及路径是否清理需人工看视频，不从隐藏状态推断。

汇总命令（只读导出文件）：

```powershell
node scripts/mp010/summarize.mjs path/to/mp010-device-results.json
```

输出每组尝试数、排除数、完成数及各指标样本数/min/median/max；不会给 P95 或“延迟降低百分比”。10 次是探索性样本，只能发现明显体验差异和异常；缺失人工判读时不算可见反馈验收完成。真实网络波动、录屏负载、iframe 视口及观察器开销都是限制。最终真实体验仍需在目标设备上复核。

## 隔离预览发布方案与回退

**本轮仅提供方案，不执行发布。** 建议建立独立临时服务 `eastfront-mp010-device-lab` 和单独 HTTPS 预览域名；两版本通过同一域名 `/v/candidate/.../` 与 `/v/control/.../` 服务，以同一网络路径和 TLS 配置接入。严禁把验收入口加入现有生产 Pages，或把客户端连到生产 Worker/Render 服务。

准备操作员在独立 checkout 固定本次准备提交，确保上述两个历史提交对象可用，执行构建与完整性验证；使用相同 Node/锁文件版本，核对交付 manifest 的摘要。只读加载构建产物，服务进程只允许一个实例，无生产凭据、无生产数据库、无生产流量，保持整个配对采样批次不重启。预览入口只对批准的测试者开放。

有两种具体启动方式：

- 局域网 HTTPS：使用已由平板信任、与测试主机名匹配的证书，设置 `MP010_ORIGIN=https://<测试主机名>:4180`、`MP010_HOST=<测试网卡地址>`、`MP010_TLS_CERT` 和 `MP010_TLS_KEY` 后启动。不得绕过浏览器证书警告；本轮不安装证书或改防火墙。
- 隔离主机 TLS 反向代理：独立域名的代理只转发到本机 `127.0.0.1:4180`，支持 WebSocket Upgrade、关闭缓存/缓冲。设置精确 `MP010_ORIGIN=https://<批准预览域名>`、`MP010_HOST=127.0.0.1`、`MP010_BEHIND_TLS=1`。模板：[preview.env.example](../scripts/mp010/preview.env.example)、[preview-proxy.conf.example](../scripts/mp010/preview-proxy.conf.example)。模板域名 `.invalid` 是占位，尚未注册或发布；访问网关/证书由预览管理员配置。

所有内部权威服务监听回环随机端口；外部只暴露同一个测试网关。配置接口只提供固定构建元数据，采样 JSON 仅留在浏览器 localStorage 并由用户下载，不上报服务。观察器不读取/导出 token、单位、坐标、完整 DOM、消息 payload 或隐藏游戏数据；正式客户端自己的身份存储仍按原机制工作。每个新样本只删除该测试 endpoint 的旧身份键，不触碰生产 origin。视频只拍测试页面，分享前排除通知或其他个人内容。

发布前待确认：独立预览域名、独立运行主机、测试者访问范围、可信证书、测试时间窗。待这些准备和下方验证均完成后，下一轮请求用户批准该隔离预览；没有批准不发布。

回退顺序：先停止测试并导出 JSON/保存录屏 → 关闭独立预览访问 → 停止网关及其测试服务（Ctrl+C/服务管理器停止）→ 如需退回此前验收包，切换整个已校验产物目录及对应夹具提交后重新验证再启动。内存房间随进程结束销毁，不恢复未知动作、不自动重发。撤销临时域名路由/访问网关时只处理此预览资源，不修改生产配置。保留报告、manifest 和导出证据。
