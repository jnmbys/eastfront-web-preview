## 时序与账本接缝

下单限定己方真实`GERMAN_RECOVERY`窗口、无待决、快照与版本一致；不改原阶段。确切起始T/快照未定，不倒填E4/E5；未来实现复用固定存档及合法阶段推进，不重新打一场战役。

2. **E11推进、E12产出**：每个已提交E最多推进一次，首个为E_a；无暂停时完成于E_(a+d−1)。地图外产能必须在E00已获准启用。最后一次推进后E12生成唯一生产回执及2 E2，归生产暂存；释放对应生产仓容预留。不是新建工厂当E立即获益，也不再次扣C。发生事务错误则该E全部回退，先前成功下单付款不退款。
3. **E14发运**：真实货物、A10资格/仓容、完整有限运力向量共同通过，才预留→实际占用；`feeEscrow -= F; handoffSpent += F`，装备生产库→在途，预留A10容量2。同一资源槽`used + otherHolds + request <= cap`；与SP共享槽须进入同一预算，无法定义/证明则不发运。失败保留生产库、F托管及同一ID；不反复生成装备。
4. **E13或E15到账**：`due = dispatch+L−1`；往期发运在E13，L=1本E发运在E15。实际核验失败则HELD仍归在途，保留目的仓容占位；以后同ID重验，不再收已付运费。成功时在途→A10不可用库存，仓容hold→resident；不是再加一份库存。
5. **下一T可用**：实际E_r入库，`availableFromTurn=r+1; shipEligibleEpoch=r+1`。不能同E再发一跳、用于T_r或伪装工厂源库跳过到账限制。E24到货写25，只留终局库存，无T25、无VP、无投入兵力R收益；未完成/在途照实保留。不保证赶上任何旧窗口。
