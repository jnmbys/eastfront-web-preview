# INDUSTRY-INTEGRATION-003 方法与复核口径

**临时口径说明：以下是已完成实验的复建方法，不是已统一的运行合同。** RULE-CAMPAIGN-001核查及与RULE-CAMPAIGN-002的待决接缝见 [CONTRACT_DIFF.md](CONTRACT_DIFF.md)。尤其不得把本方法的假定入场或集结维护作为正式规则；本次保留参数、流水、审计和计算结果，不重算。

本轮沿用 [002方法](../industry-exp-002/METHOD.md) 的人员、成品、残骸、SP分账、逐单位攻击和单走廊装运算法，只改变研究的终局边界。所有参数在 [PARAMETERS.json](PARAMETERS.json)；计算在会话内临时执行，没有新增可运行代码或导入Core。

## 终局差异

002主表H16以及其长24附表都使用旧胜利生命周期的德军最后窗口口径：没有最后E，最后T不施加外生战损、不恢复、不新编。本轮为与Victory-024设计对照，主表H24改成T1—T24、E1—E24，最后T仍受外生战损且可以恢复，最后E仍生产/到货/维护。最后T不下新编订单，因为下一可用窗口T25不存在。

这只是单侧能力账本的24次窗口加24次结算。对手动作以固定损失序列替代，未执行双方的真实24个回合、占领、VP或崩溃评分。T24恢复的价值可在候选Victory的兵力压力中体现，虽不再获得下一己方攻击窗口；末轮回收成品、原产装备和运到仓库的货不直接降兵力压力或送VP。

差异含末轮外生战损和恢复休整，不能把全部变化归于多配送一次。H8/12/16/20反事实也使用各自最后E；它们不是当前旧规则的同长度实战结果。提前终局发生后的账本不会继续发货计收益，本轮只是用这些期限检查可用窗口，未模拟触发提前胜利的地点变化。

## 可独立复建的结算

对路线r和期限H，维护单位表：永久ID、出生可行动回合、存活、伤阶、SP库存q、D和伤口时间队列。4q=1SP。成品和残骸以半E为整数基本单位，输出表换算E。初始O01—O08各12q、D0，O01/O02各一阶伤；后方/前线成品0、P60、残骸1E。

每T从3到H，对索引(t−3) mod 8的旧单位施加一阶损失；若目标已死则跳过。每个实际损失形成0.5E残骸，三阶伤消灭，剩余库存计销毁。损失不随攻击频率、输赢或地图反馈，因此仅能检验资源传导，不能校准战争消耗。

在存活受损、D<2单位中按最早伤口、ID选人。若已有1E＋1P，则预留一人恢复；其余单位按ID顺序各得一个假想目标，目标受场景上限限制。扣费p=min(4,库存q)，因子取 min(0.5＋0.5p/4, 债务因子)，债务因子依D<1、1≤D<2、D≥2为1/0.75/0.5。阶攻值依伤阶0/1/2为5/4/3，有效攻值向上取整。因子1计满效，否则计减效。之后执行预留恢复，消除最早伤口并扣1E＋1P。

若t<H且恢复后仍有3E＋3P，最多新编一支、扣费、库存0，T(t+1)假定合法入场行动。在本E于集结地承担维护；这是一项明确的研究接缝假设，不是付款就已占地图或已计Victory的R。新兵训练、部署路径、入口阻塞未建模。T24不新编。

每E先原产入后方，受24E仓容限制。A只在E1另加12E急拨；B从E4额外原产2E；C从E3消耗残骸最多回收0.5E入前线，受前线仓容限制。B原产仓满时不产生递延生产额度。末轮自动发运仍沿用此前政策，并非最优终局调度。

设净维护补入需求m为所有维护对象 max(0,4−库存q)之和。若m超过物资来源或共用运力，当E不发装备；否则先留足m可运输空间。想发成品=min(后方库存,4E,24E−前线−在途)，再受预留维护后的运力限制，每E成品占1运载单位。SP与E分享总运力，各1单位负载。运输L=1在本E末到库，下一T可使用；L=3在发运后第二个E到库、第三个T可使用。只扣发运边界负载，不是完整逐路段车辆在途模型。

余下SP预算=min(来源上限,运力−装备发运)，先逐q给最低库存者补到4q，再抬至16q。平库存按存活单位插入顺序，以t mod 存活数轮换打破平局；未用来源额度不留存。每单位支付最多4q维护，足额D减1到最低0；短付则D加短付比例、封顶3。若本E短付且更新后D=3，再损失一阶，SP销毁和残骸仍记账。主样本足额，来源6样本覆盖耗损与死亡。

本算法没有调用真实多路径优化器。只有一种步兵，未收费机动燃料、坦克维护或维修运输返程。工业区域在地图外，战区通过抽象接收点拿货，未把工厂塞入640格或改地图。

## 守恒与指标

逐行成品：累计原产＋急拨＋回收＝后方＋前线＋在途＋累计恢复阶数＋3×新编数。

逐行人员：60＝剩余P＋恢复阶数＋3×新编数。残骸：1＋0.5×全部实际损失阶＝残骸余量＋累计回收。SP：初始24＋实际来源发出＝当前库存＋攻击消费＋维护实付＋死亡销毁。

装运E＋发出SP≤共用运力；SP另受来源额度限制。在途累计发出−累计到货＝当前在途，不重复到货。回收返还的是装备，不能增加P、I或消耗性SP；修复没有另收RP。

运输目标压力＝(想装运成品＋把所有维护对象库存抬至4SP上限所需物资)/容量。它不是维护缺口。恢复能力是本行动窗口开始时，在位置等资格假设成立的前提下，当前前线装备和P能恢复的阶数，上限1；不能用本E晚到货回头支付。恢复等待＝恢复T−受伤T＋1，表示到下次己方行动的编号距离；初始伤口时间未知，不进均值，期末未完成伤口单列积压。

## 条件组与可追溯性

SENSITIVITY.json保留13组各A/B/C/D汇总、工业24点、运输维修9点、期限5点，以及来源6SP的完整逐单位流水。只有同组比较具有共同条件；D不花12I，C组件拆分分别花8I或4I，未用钱不折算隐藏福利。

数据JSON字段沿用002；trace.units.stock为q、trace.inTransit.e为半E，其余行表的SP/E已换算。recoveryEligible是候选人数，recoveryCapacity是资源与数量限制后的能力，recovered是实际执行量；单位伤阶不是伤亡人数。trace记录本E结束后状态；其unitActions记录本轮扣费前数据，不能用结束库存反推当轮满效判定。

AUDIT.json记录52次推演1248行、29561项独立重算断言；计算自身还逐行检查四账守恒。主数据包含三路线与D完整流水，可复核每次攻击、库存和人员。扫描点也执行相同内建守恒检查，但29561的计数只包括13组及旧口径复现，不把扫描重复计数。

没有新代码意味着这些离线断言不是仓库自动测试套件。方法、完整主流水与敏感性摘要用于人工或独立重建；它们不证明Core合法性、求解器等价、双方胜利结果或多人性能。
