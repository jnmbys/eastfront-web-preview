3. 固定属性与同样供给/地形下，累计一小时的期望损耗在不同切片一致；真实五分钟函数按全骰组合计算均值。另列方差，不把期望一致误称逐步轨迹一致。
4. 原48强制样本只读对照；R1代表性允许撤退的权威样本另列；不禁止撤退或强制贴身。781283/914117仅检查，没有据结果调参；本轮无调参，也不新增挑胜种子。
5. 运行R1相关回归；如果运行代码没有变化，引用同48小时脚本已有结果及代码/证据哈希，不重复正常战役。不修改库存/运输/存档格式，不更新4275进程或任何用户档。

## 最小待核实项

- **组织合成**：1.19.2.0＋固定BICE、固定已生效科技/HQ/装备条件下，单步兵、步兵＋炮、步兵＋工兵的最终组织度，及负数项/支援项的平均分母和下限。当前两种简单假设不应任选一种上线。
- **强度与装备**：一次明确受击的raw强度、人员、装备前后量；装备回收是在停止交火、撤退到达还是战斗组结束，回本单位还是国家池；歼灭与包围例外及小数处理。不得把“.60”推断为人员返还率。
- **时间与撤退**：固定引擎每小时攻击判定、骰的抽样位置及伤害应用时点；最低战斗时间的适用范围，撤退期间是否仍贡献/承受火力。需要引擎行为证据，不需要新一轮全量环境准备。

本轮不对这些未知项制造临时倍率、回收池或新的强度条。R2交付语义审计与执行检查，运行仍为R1；不能称为已完成黑冰数值对齐。作者检查后交Leader审查。

## 实际发现与本轮修正

补核诊断口径发现：原定向脚本的losses来自clock.units.losses，累计的是请求伤害（含小数与末次超出剩余人员的伤害），并非整数人员账本。手动步炮219031第78步：请求累计1260.132，实际国家损失1250、收到补员0、剩余0。不能把超出的10.132解释为补充后又损失。

本轮修复诊断输出：明确命名requestedDamageCounter，另列actualPersonnelLost、真实补员和整件装备损失，并逐阵营验证“初始人员＋实际到队−期末人员＝实际损失”。不改原始R1文件，不改变权威战果、扣库或人员，不把这一修正宣传为降低伤亡。正常48小时报告本来使用国家账本，2771/2742与2461/2823的对照不受该口径问题影响。

固定属性的真实5分钟函数全骰组合均值：所选步兵攻击者每小时承受HP期望0.41076、组织期望0.3423。1/5/10/60分钟的解析切片累计期望一致，随机方差不同；只有5分钟执行真实内核，其余为解析参考，不是另外运行的游戏时钟。角色攻防不对称、状态随伤亡改变后，不能用此常量预测整个战斗时长。

保持35组织时，一营25HP与八营200HP完全不同：按当前损耗比例达到18%组织约需34.44HP；分别等于满HP的137.76%和17.22%。这说明营级战斗群的规模/组织合成是解释问题的重要条件；不能从单营强制死亡推出BICE .10/.05必然不合理。八营仅作现有合法槽位的属性敏感性计算，未替换开局或注入部队。
