## 验证结果

| 范围 | 证据与结果 |
|---|---|
| 真HTTPS/WSS | 临时自签测试证书，协议客户端显式传CA，未关闭证书校验、未安装系统信任。首进程直接TLS；真正重启后改为受信回环TLS卸载夹具，Host/Origin不改写，WSS恢复及保存通过 |
| 双人 | 两个独立签名Cookie创建/加入，各下一条己方合法命令；重复招募一次生效；第三人入席/读档、跨席会话、越权命令、错误Origin/Host拒绝 |
| 时间与恢复 | 苏军继续拒绝；房主继续；断线暂停、苏军原席重连。正常结算12步产生14批在途（测试驱动时钟，不注入资源）；重启后身份、地图、队列、在途、库存和优先级摘要一致，默认暂停，再次保存 |
| 旧单人 | 用原三个引擎生成合成原局，原Cookie格式继续访问并恢复；旧身份不能使用MP接口，新身份不能读取旧局。第三场触发现有2场加载上限，待30秒空闲回收后继续成功，未放宽上限 |

| 代理边界 | 仅可信直连IP+单一https协议头通过；缺头、http、逗号链、假转发Host、非可信IP伪造头均拒绝 |
| 离线备份 | 保存并真正停止进程后复制两命名空间/密钥、核对哈希；恢复至两个空目录，启动新进程，原身份仍回同一房间并能保存；篡改备份被拒绝。在线备份拒绝 |

## 限制与审查重点

- 本机Windows、Node24，协议CA显式信任；没有Linux发行版或Docker运行环境可用，未安装。Linux持久盘/停机、实际托管代理来源、远程双人、真机及持续绘制未验。
- 线上配置、费用、凭证和存档未查询、未操作。实际平台的TRUST_PROXY_IPS必须来自可信接入信息，不能猜值或填任意网段以放行。
- 运行锁是防双写锁；异常退出需要确认死进程后处理遗留锁。备份程序有意不在运行中取“不一致快照”。
- 新旧目录要求为互不包含的独立目录，修正上一轮发布单建议嵌套目录的不妥之处；旧目录保持原值，新目录选择同一持久盘上的兄弟目录。
- 复用原身份系统，不增加公开匹配/限流平台或假定无限并发容量。该候选交独立审查，不自行宣称公网或总体安全验收完成。

具体启动配置、备份/回退与上线后的检查见 `RELEASE.md`。本轮不Push、不合并、不部署；用户最终批准前不更改公网。
