### 代理判断与剩余访问缺口

[Render Web Services](https://render.com/docs/web-services#connecting-from-the-public-internet) 明确平台负载均衡器终止HTTPS，再向服务HTTP端口转发；公开用户不能直接访问该端口。因此实际候选应使用**平台TLS卸载的HTTP接入**，不是要求平台改成向应用发送TLS，也不是部署本地双回环代理。

不过，现有精确IP信任检查还需要实际直连 peer 地址、可维护的地址范围/稳定性依据、平台如何处理 X-Forwarded-Proto/Host 的证据。get_service未提供这些；文档说明SSL终止，但没有提供可直接填入本项目的固定代理IP清单。出站IP与服务 ipAllowList 不是代理身份依据。不能猜填127.0.0.1、私网网段或0.0.0.0/0，本轮未放宽校验。获取方式：在已授权运维访问下核对实际服务连接元数据，并向托管方核实该地址的信任与变化保证；在此之前公网代理适配仍未闭合，不能宣布直接可发布。

[Render Disks](https://render.com/docs/disks) 说明仅挂载路径内数据持久、磁盘可跨重启保留；当前API证实配置，不证明运行时mount、空间、目录权限或写入恢复。

本轮尝试只读SSH `df -h /var/data`，严格主机校验返回：`No ED25519 host key is known ... Host key verification failed.` 未关闭StrictHostKeyChecking、未添加未经核验指纹、未读取凭证。还缺可信SSH主机指纹及有效Shell访问；也可由已登录控制台提供只读结果。当前实际SAVE_DIR、拟用MP_SAVE_DIR是否存在/重叠、可用空间和运行用户权限未重新取得。历史741MiB不作当前结论。本机无可用WSL发行版或Docker，未安装环境，Linux启动/停机保存仍未测。
