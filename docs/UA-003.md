## Presence architecture

The rule chain remains Action → RulesEngine → accepted ActionResult → canonical GameState. The presentation observer derives detached facts only after state adoption. UA-002's coordinator retains the only animation clock, queue, speed controls, motion profiles and interruption policy.

At map remount, `UnitAnimationRuntime` projects only `{id, side, type}` from canonical units. `SvgUnitPresentation` binds those identities to **already visible canonical Counters**. No hidden deployment unit gains a presence. Counter transforms, widths and stack offsets supply the artwork anchors; no alternate hex geometry is computed.

`UnitPresenceLayer` inserts one inert group **before the whole Counter layer**. One shared definition bank supplies reusable SVG bodies and details. Individual units use small groups and `<use>` instances. Every presence node has `pointer-events="none"`; the layer and unit roots have `aria-hidden="true"`. No role, focus target, gameplay identity attribute, hex, hitbox or event handler is attached. Counter V2 and its original enlarged touch rectangles remain the information and interaction surfaces.

The renderer writes the same UA-002 parent transform and opacity to Counter and companion in one paint call. Local pedestal, orientation, muzzle emphasis and collapse are presentation details only. There is no second animation engine, GameState clone, per-frame Core query or gameplay random draw.

The mapping covers all 12 types in the 17 existing templates. It creates no gameplay unit, weapon model, calibre or new type. German blue-grey/cool steel and Soviet muted red-brown reuse the established faction language. Contact shadows and restrained top-edge highlights provide depth without textures. No downloaded assets.

Presence widths are approximately 0.7–1.1 Counter widths for the major families. Both normal and heavy models scale down with an existing stack. The HQ is deliberately compact. All Counter numbers, NATO symbols, damage marks, selection and stack badges are untouched.

## LOD / composition / stacks

Far hides the entire presence layer. Medium uses 0.78 artwork scale, reduced opacity and no detail strokes. Close exposes the full silhouette and detail layer. The existing screen-hex-width LOD selector is used with a two-screen-pixel presence-only hysteresis band to prevent pinch-boundary flicker. Terrain and Camera thresholds are unchanged.

A MutationObserver watches only the existing map `data-zoom` scalar; ResizeObserver refreshes the cached fitted width on actual resize. Neither writes Camera state. Idle presence has no RAF. LOD changes adjust attributes on existing elements rather than recreating them. Both observers disconnect on rebind/disposal.

Each presence root uses its own exact Counter transform. A small display pedestal shift uses the existing stack offset's sign to keep two companions separate; it never changes Counter or hex placement. All miniatures render behind all Counters, so dense adjacent stacks prioritize formal information over decorative silhouettes. The decorative extensions do not add a separate clickable region; input passes through to the unchanged Counter/Hex routing.

## Movement and combat integration

MOVE, RETREAT, ADVANCE and BREAKTHROUGH reuse the exact accepted paths, motion profiles and timing constants from UA-002. The Counter and companion share the complete parent transform throughout travel, hit and settle.

Accepted combat playback remains windup → short staggered fire → reaction/loss → accepted tactical movement. Fire emits only after `CRTResolved`. The presence receives the existing participant target direction and unit-character recoil, plus a compact vector cue. All actual attackers remain in the attack group. No camera shake, projectiles, particle system or automatic recenter.

Attacking **and defending** supporting artillery now have independent firing participants, derived only from the resolved `CombatTransaction.context.attackerArtilleryUnitId` / `defenderArtilleryUnitId`. Drafts, nearby guns or transaction declarations alone do not prove firing. Supporters are kept separate from `attackerUnitIds`, deduplicated, and included in the existing capped stagger. Defensive support faces an actual attacker. No extra rule fields or support validation are added.

Hit adds brief base emphasis while retaining the Counter's canonical damage display. On accepted destruction, the companion becomes an inert ghost immediately, then fades and drops/tilts slightly with the existing destroyed phase. Completion, Skip, Instant, reduced motion, hidden map, new game and disposal remove the ghost. Reusable fire shapes return to zero opacity; no transient phase remains. Normal/Fast/Instant and reduced motion yield identical final presence DOM and canonical state.
