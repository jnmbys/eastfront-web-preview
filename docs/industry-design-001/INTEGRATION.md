# 与现有机制的衔接表

这是后续实现建议。本轮没有删除、停用或修改任何现有机制，所有运行入口保持基线原样。

| 机制 | 当前事实 | 推荐处置 | 兼容/避免重复收费的规则 |
|---|---|---|---|
| RP初值与REPAIR_UNIT | 德8/苏12；按模板1或2RP修一阶 | 旧规则模式完整保留；新工业新局保留开局RP为“既有补充承诺”，逐步由P/装备支付新增恢复 | 同次恢复二选一：消费旧RP承诺，或消费P/装备；绝不RP+P+装备一起扣。RP承诺本身已包含该次人员和装备，不能另发一份同等P/装备库存。候选初始P/E预算必须明确扣除被承诺覆盖的部分，不自动给旧RP估现金兑换率 |
| 修复合法性与吞吐 | 自有控制权、恢复阶段、未移动/攻击/支援、非敌邻接、基地≤2、正常资格、每单位一阶、德1/苏1→2→3 | 保留。更大工业库存不能越过恢复单位上限 | 未来若修改吞吐单独评审；现有expSupply的资格来自债务，不能又追加旧半径惩罚。材料不足拒绝时不消耗恢复名额 |
| 苏军定时增援13槽 | T4/7/10/13/15；永久槽ID；无需RP | 第一版完整保留，解释为国家级已装备部队调入；与本地新编并存 | 固定增援已经在上级预算付过装备/人员，不再收P/E；也不能拆成免费可交易库存。新工业预算是额外明确限额，需随剧本总兵力评估，不以此宣称原难度保持 |
| 强制增援/延期 | 有合法入口的可用增援不能Ready跳过；堵塞的迟到槽保留 | 保留，不借工业施工延迟来取消历史增援 | 本地新编用独立订单ID与命令，不能冒领历史槽或复用被消灭ID |
| 德军新部队 | 无现行苏军式定时表 | 仅未来工业规则新编提供候选部署入口/资格 | 不能默认为德军已有DEPLOY_REINFORCEMENT实现；这是需要新接口的设计范围，文档未新增运行单位 |
| 装备型号与编制 | 固定templateId与三阶数值，HQ例外 | 保留预设，另加静态L/H/V材料配方；HQ及精锐开放由剧本限制 | 材料配方不改攻防MP；恢复只让step回到既有阶数，不叠加“工业攻击加成” |
| 初始部队SP | 完整战役部署授予3B、上限4B，初始库存入总账 | 保留原开局方式 | 新工业部队及定时增援携行0；不可重用初始部署分支重复领3B |
| SP来源 | 固定来源发出实际使用量，未用额度不结转；源与仓不同 | 保留其契约及版本；工业装备产能另账 | I、L/H/V不是SP。运输升级只释放运输约束；不自动增加SP来源，也不把未用SP额度变装备 |
| 维护、债务、伤亡 | 维护B按现行类型；欠账持续；后勤损失落Core一步一次 | 保留，新增部队加入同一账 | 补旧材料不支付本期弹药，SP不代替装备。一次后勤步损只产生一阶损失，修复后不清债；无单位复活 |
| 攻击/普通机动消费 | 直接攻击最多1SP/单位；装甲/摩托普通MOVE最多1SP；防御/强退不另收费 | 保留 | 不按攻击再扣1H或按移动再扣1V。装备是资本存量；真正步损的设备损失另记 |
| 原RAIL_REPAIR | 一次计划、4/5边、工兵机会成本，无SP/RP工程费 | 基础修通能力完整保留；经济建设只新增吞吐/仓储/装卸候选 | 不对同一条既有修路行动追加I税。新建线路或恢复新设施须定义为不同项目，不能付钱绕过ZOC、所有权、桥合法性 |
| 共享运力/桥/W/T | 来源、铁路、共享桥、枢纽工作量和运输工作量分开限额 | 保留所有物理边界，设计新装备货运预留接缝 | 预留与SP残余容量加起来不能超过原/已完成项目后的同一容量；每笔货只扣一次；这里未变更补给参数 |
| CP/HQ命令 | 既有指挥点收入与命令功能 | 全保留，与I分开 | CP不能通兑建设I；不把EXTRA_SUPPLIES当无限工业来源。现有015的HQ/炮兵支持面仍须据代码能力判断 |
| 占城/占厂 | 当前有控制与补给源事实，没有完整工业缴获制度 | 最小版不新增占城自动I收入；抽象后方不能由当前格直接占领 | 若后来实体扩图，敌占先冻结可用通路/资产，战利品、损毁和修复规则另立，不能把control:null猜成资产易手 |
| 胜利、阶段和RNG | 默认T16德军末终局、此前可提前胜；补给每turn递增结算一次 | 不改胜负、阶段、骰点；工业epoch跟随既有完整回合边界 | GAME_OVER不发最后一轮产出，不把未完工项目折胜利分；玩家回合≠完整回合，不双算 |
| 旧存档/模式 | 015会话模式固定，独立实验；生产多人另有服务 | 新局选择显式工业版本；旧局继续原规则 | 不静默转换存档或给旧局塞工厂。版本转换需要资产、RP承诺、增援槽、SP四账一次性迁移记录 |
| 多人授权与回滚 | 权威revision、actionId、按查看方投影；015整包失败不提交 | 复用并扩展同一个原子事务，新建阵营经济授权角色 | 多人Ready不重复领产；超时不吞钱；重连不能重复出货；不在客户端计算权威库存 |

推荐分阶段衔接：先只评审静态配置和账本；再在独立实验规则版本中验证“P/E恢复＋单队列新编＋有限建设”；待补给 Worker 确认装备预留和SP共享预算后，才进入可操作战役；最后独立做多人和性能验收。这个顺序没有授权本轮修改或删除现有系统。
