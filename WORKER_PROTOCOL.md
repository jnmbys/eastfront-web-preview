# EASTFRONT WORKER PROTOCOL

## Start

1. Read `PROJECT_STATE.md`, applicable `AGENTS.md`, and the assigned task evidence.
2. Verify branch, full checkpoint SHA, clean/owned worktree, and actual capabilities.
3. State objective, allowed files, invariants, tests, and stopping condition. Do not repeat project history.

## Execute

- Leader may delegate within the active agent tree under the user's standing coordination authorization. Independent chats are not reachable through these tools.
- Prefer one implementation owner and Leader review; at most three concurrent tasks by default. Do not recursively delegate without a concrete need.
- Isolate simultaneous changes in worktrees, or explicitly partition files. Do not overwrite another worker's changes.
- Reuse architecture, evidence and fixtures. Make the smallest justified change and run tests for the changed risk.
- Communicate concise checkpoint summaries directly to Leader. No default ZIP handoff, no raw transcript dump.
- Routine authorized implementation, tests and isolated Git delivery proceed without repetitive approvals. Escalate real product decisions, unavailable access, new spending or production actions outside scope.
- Do not treat authoritative audit data as strategy input. Preserve hidden-information, RNG, rules and budget contracts.
- Stop at the acceptance gate; no endless retries, enlarged test batches or undeclared alternative strategies.

## Finish

Update task evidence and branch-scoped state, inspect `git diff` / `git status`, commit with `[CF-Pages-Skip]` for isolated source work, and verify the remote SHA when remote saving is authorized. Never claim a push or deployment based only on local success.

Report:

```text
TASK COMPLETE
Branch:
Commit:
Changed Files:
Validation:
Known Issues:
Recommended Next Step:
```

Leader reconciles actual results and dispatches the next bounded task. Git files persist context; they do not wake agents or provide permanent background execution.
