## 实现与边界

`adapter.mjs` 复用 CITY `Campaign.transaction / receipts / snapshot` 及已有 `Delegation.config/tick`。没有战役引擎、自动推进旧阶段或浏览器代军官逐步请求。军官检查节拍500ms，授权推送检查150ms，显示rAF独立。实际模拟语义仍属于旧CITY，后续只替换适配器接入已固定SHA的新玩法时钟。

支持MOVE、BUILD、PHASE及军官OFFICER/PAUSE；这是最小通信面，不是完整攻击、生产或战役UI。命令顺序按席位单调递增，身份绑定实例、请求ID、序号及信封签名。接受/拒绝元数据挂在原权威回执，BUILD/MOVE仍由原事务扣费/执行，军官配置使用原验证并原子回滚到同一回执容器。没有独立资源账本。

全局revision不是唯一门禁。MOVE/军官命令验证本方单位依赖（单位状态、补给、已公开阶段及委托），BUILD验证本方账户依赖，PHASE验证阶段；再用当前版本调用原权威校验。另一部队或另一方配置导致的总版本推进不一律拒绝。排队意图不悄悄更新依赖或改内容；冲突后明确拒绝，由用户重新规划。旧CITY依赖粒度不等于新玩法规则，新tick状态的真实依赖需由新适配器定义。

客户端保留本地选兵/相机/目标和待确认队列；不改正式占领、损失、扣费、库存。选兵的新合法菜单确实需要一次SELECT查询；等待时可规划但普通MOVE提交仍要求选中对象、选择ID和当前版本的合法菜单。动作完成后服务器推送授权状态**及当前选择的合法菜单**，没有自动“snapshot后再发QUERY_MATCH”的一轮往返。军官持续意图允许先提交给权威验证，虚线路线不表示批准。

状态先经 `Campaign.snapshot(viewer)`/原FOW投影，再转成永久ID索引对象后作递归差量。数组替换、对象set/remove，静态地图/交通只在首个完整视图或真实改变时发送；不逐帧发送地图、历史账本或规则配置。失去可见性的实体删除，不把敌方隐藏状态送出再让浏览器隐藏。必要本方账户、城区、军官与当前菜单随状态更新。

每连接一个未确认状态，baseViewVersion严格等于客户端已应用版本；viewVersion单调且重同步不会复用旧序号。等待确认期间只保留最新状态需求；业务结果来自原回执，不能被合并丢失。有空位时结果与状态同包，否则结果先送、授权状态随后。基准不符完整重同步；15秒未确认状态关闭连接后恢复，不无限积压。

新连接替换旧connectionEpoch；客户端既检查当前socket也检查epoch/实例/版本。同请求恢复保留原ID、顺序、内容；迟到确认使用先前实际视图应用时间，不把确认时间当作应用时间。客户端收到/持久化结果后确认回执，但原权威幂等记录不淘汰。原CITY不具备可靠跨重启存档，因此新实例明确不自动重放旧指令；新玩法存档应保存同一回执与序号游标，见交接文件。

有界策略：客户端最多16条未完成意图；每方向128条/2MiB排队，socket缓冲上限2MiB；权威执行队列32；业务回执与军官回执各4096上限。达到回执上限停止军官并拒绝新业务，旧结果保留，不用静默淘汰来省内存。一方连接差只影响其推送；已接受任务继续执行，另一方不等其ACK。旧阶段若需要该玩家推进，仍按旧规则等待，不能称新版不间断战役已通过。
