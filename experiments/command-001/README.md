# COMMAND-001 战役指挥候选

这是主游戏地图上的可玩候选，不是工业面板。新增一个可选作战目标、相关部队定位、授权态势问题和已执行行动摘要。原地图、美术、移动、攻击、战后处理、恢复、筑垒及阶段提交均复用既有实现。

## 先看效果

- `evidence/command-plan-1440.png`：同一目标、两支相关部队和计划主攻方向。
- `evidence/command-pending-1440.png`：真实攻击得到 AR，原 Core 要求选择撤退格。
- `evidence/command-result-1440.png`：两次攻击均撤退后的真实位置，计划目标仍在原格。
- `evidence/original-result-1440.png`：原界面完成相同业务后的状态。
- `evidence/command-result-1024.png`：平板视口。不是实体平板验收。

图上的金色虚线是计划，绿色实线是本回合已执行的己方路线。已知控制区来自原玩家投影，不能当作敌军战线；未知控制不填色。敌军离开视野后只显示原有接触／记忆标记，不把“看不见”解释成消灭或撤离。损失事件若发生，会显示红色历史位置标记和授权摘要。

## 三个问题的结论

**能否更快看懂局势？** 候选把当前目标、己方受损与补给问题、当前可做事项放在同一处，并将真实移动和撤退留在地图上。它减少了需要记住的位置和重新查找的入口，但本轮没有真人理解耗时实验，不能声称已证明看懂得更快。

**能否围绕一个目标连续操作？** 可以。浏览器实跑了标记目标 → 第一支部队移动、攻击、撤退 → 快速选中第二支部队对同一目标攻击、撤退 → 检查实际位置。没有重新填写目标，没有自动作战。另实跑到 T10，计划仍保留；换边交接时地图遮挡，另一控制者看不到该计划。

**标记帮助指挥，还是增加负担？** 两者都有。在这段短任务中，它提供稳定的部队定位和目标参照，但增加 4 次标记操作，桌面还多 1 次揭示操作控件的滚动。不能把本候选描述成更省点击。它更适合持续若干回合的目标组织；一次性动作可以完全不用标记。是否值得推广仍需真人使用反馈。

## 启动与普通对局

需要 Node.js（验证版本 24.19.0），运行本机静态工作台不需要安装依赖。

```powershell
node experiments/command-001/serve.mjs 4190
```

也可执行本目录 `Start-Command.ps1`。关闭终端服务：**Ctrl+C**。

| 入口 | 用途 |
|---|---|
| `http://127.0.0.1:4190/?command001=1&commandScene=1` | 可玩 T9 片段；点击新游戏进入 |
| `http://127.0.0.1:4190/?commandScene=1` | 相同 T9 起点的原界面对照 |
| `http://127.0.0.1:4190/?command001=1` | 正常部署、正常本机对局，部署结束后启用候选 |
| `http://127.0.0.1:4190/` | 保留原入口 |

如需 FLOW-001，可另外加 `&flow001=1`。其开关位于“独立 FLOW-001 开关”中，默认关闭，仍只自动提交满足原保守条件的本人空恢复准备；COMMAND-001 不扩大自动推进。

候选只启用于 `127.0.0.1` 的显式查询开关。没有联机指挥候选、队友共享计划或新 AI 行为。规划功能适用于固定本机 Core 的普通对局：按控制者保存到当前内存会话，跨阶段、跨回合保留；刷新／新游戏后不保留。删除 `command001=1` 恢复原布局，但页面刷新会按原本机行为丢失内存对局。

Shift 点己方算子加入／移出计划；触摸或不用键盘时，先选单位再点“选中部队加入计划”。点“标记目标”，再点地图；起点默认取首个成员的当前位置，可点“修改主攻起点”调整。成员按钮复用原单位选择并定位地图；不改变属性、编组加成或行动资格。取消计划只清除标记，不能撤销已生效动作。无法在当前投影定位的成员不会凭空补位置，可以移除记录。

当前阶段的原动作面板位于目标区下方；阶段未到只给说明。攻击必须通过原合法预览和确认，战后选择继续锁住阶段。候选没有新的一键跨阶段动作。

## 合法复跑起点与业务

种子 **17001**，真实 **640 格**战略重置 F 地图。`fixture.mjs` 逐项通过原 Core：58 次合法部署、2 次部署准备、正常阶段结算和 2 次可部署增援；共 **143 个接受的动作**到达 **T9 德军移动阶段**。`setup-actions.json` 保存完整序列，`start-state.json` 保存结果。没有直接覆写单位、资源、回合或 RNG 来制作这个主片段。

这是固定脚本通过规则生成的合法中期局面，不冒充人类实战存档。前八回合选择不移动、不攻击，并按原规则处理补给和可部署增援；因此不能把它当作典型中期战线的代表。本片段德军存在补给问题，攻击强度仍按原规则处理，没有补发资源。

1. 计划成员 G-I-01、G-I-02；目标 `3,4`，主攻箭头从 `1,4` 指向目标。原界面对照不建立标记。
2. G-I-01 从 `1,4` 实际移动至 `2,4`，手动结束移动阶段。
3. G-I-01 单独攻击 `3,4` 的 S-I-01。原骰子 **1+5=6**，结果 **AR**；选择撤退至 `2,3`。
4. G-I-02 再次攻击同一目标。原骰子 **2+3=5**，仍为 **AR**；选择撤退至 `1,5`。
5. 重新选中 G-I-01 检查位置。目标未被这两个动作占领；计划箭头不会被画成已完成推进。两次战斗实际步损均为 0，也没有实际推进。

这不是推荐战术，尤其不能借验证中已知的骰子结果向普通玩家预告输赢。其用途是验证失败、待决和连续操作能否正确表达。

## 实际操作对照

桌面 1440×1000，同一起点、同样镜头初始位置、同样业务选择。两份独立浏览器对局操作原界面，所有业务经原交互提交；双方使用相同的减少动画偏好，不作速度比较。测试只读诊断接口没有写状态能力。

| 指标 | 原界面 | 候选 |
|---|---:|---:|
| 点击／Enter 激活（含进入片段） | 15 | 19 |
| 其中计划标记 | 0 | 4 |
| 其中结束阶段 | 1 | 1 |
| 揭示被遮挡控件的滚动 | 1 | 2 |
| 业务决策：移动、两次攻击、两次撤退 | 5 | 5 |
| Core 动作 | 8 | 8 |
| 业务网络请求 | 0 | 0 |

滚动单列，没有藏进点击差值，也不把一个滚动视作固定耗时。算子选择使用原有 Enter 激活，候选相关部队按钮用点击；两者均计一次。选择目标、路径和部队等必要操作都在逐项日志中。测试工具揭示控件的滚动不是经过测量的真人手势数；未统计认知时间。计划修改和取消另行验证，未混入主业务对照计数。

## 验证与信息边界

```powershell
node experiments/command-001/verify.mjs
# 服务器保持运行；浏览器验证需要已有 Playwright 和 Edge
$env:PLAYWRIGHT_MODULE = 'Playwright/index.mjs 的完整路径'
node experiments/command-001/browser-verify.mjs
```

`rules-comparison.json`、`browser-comparison.json` 和 `final-state.json` 为主对照；`mode-regression.json` 记录原模式、FLOW 单独、COMMAND 单独、两者同时以及普通部署入口。另回归 FLOW 原规则层验证，旧文件未变。

候选展示层不读取 GameState，使用原授权 render model／player view；事实摘要只订阅原系统已授权的 presentation events。历史事件按会话、控制者隔离，当前不可见不等于被消灭，历史路线不等于当前敌军位置。每个状态下的动作入口仍由原查询、校验和提交门禁控制。

单独标记 **SYNTHETIC** 的针对性检查包括：拒绝敌军加入计划、待决不能改目标或成员、不同控制者／会话隔离、未知控制不填色、缺失敌军不宣称消灭。另把已有己方单位位置调整为合成 4:1 试验局面，真实调用原 Core 得到 D1R，检查实际损失、撤退、推进事件及其授权归属；它不是主片段结果，更没有替主片段制造胜利。

没有真人理解速度测试，没有实体平板、多房间联机或工业扩展验收。普通对局里复杂多部队战果、大量历史标记和长时间组织负担仍需使用反馈。历史摘要只保留本视角最近 12 条动作事实，地图路线仅显示本回合最近 3 条；原战斗结果历史仍在。
