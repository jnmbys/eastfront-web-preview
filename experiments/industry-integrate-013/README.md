## 事务、资格和归属

`Transactions`继承完整012根，新增人员账和同match唯一登记。进程内同match只有一个所有者，改实例名不能重复建立。来源、拨款、包、申请、运输及到账永久ID按决策/match/G/personnel生成；重试先查永久回执，历史回执不替换当前根。相同ID冲突拒绝。不同请求引用同一已成功导入/申请只返回历史信息，不新扣费、不新登记库存。

`personnel.package`是唯一人员实物账；来源/运输/后方数量均从它的唯一owner/custody推导。`warehouseRegistry`只映射一个既有`RC007-REAR-G-A10`：E2权威仍为012装备仓，P容量新增1。旧012的P=0字段原样保存为历史字段，明确排除为当前P来源；不能把它与人员视图当作两个同格仓相加。

每次发运/收货都读取原Core当前全量权威状态，用原完整性及ZOC检查确认A10/0,9。null控制仅按本轮G例外放行，敌控、敌占、敌ZOC或字段未知拒绝；不写control/homeSide。检查所有已用/预留LQ以及P驻留/入库预留。派生只读视图和调用方声明都不能替代资格。

真实E只能由原`live.execute`合法跨T及双方SP结算记录触发。E7私有根内记录E14发运付款/使用能力、E15到账、再按真实新turn开放T8。整个边界与原游戏/SP、人员、预算、仓位、epoch、回执只发布一个新根；队列取得执行权后的总预算3秒，覆盖Core、SP、资格检查及提交前检查。初始化校验和求解器预热不属于游戏事务。

任何提交前错误连同临时回执一起回滚；更早成功事务不撤回。拒收是已发运后的正常HELD结果：实物留在同一运输包，保留A10预留，已付费用和已用能力不退款。若事务本身异常，则游戏/SP也不推进。
