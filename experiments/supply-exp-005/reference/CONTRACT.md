## 两条状态线

Core 状态仅由固定种子 3001 的 accepted Actions 产生。使用旧 Core 补给、战斗与恢复。影子库存、短缺债务、影子减员不写回 Core。Core 的 step 与影子 strength 分开；Core 战损改变 core_step，不额外叠加影子损耗或降低原模型 B/库存上限。Core 消灭才移除物流单位。影子 strength=0 仍保留身份，不因下一快照复活。

片段按钮向前重放一段已核验 Action 的终点快照；并非每按一次只发一条 Action。影子时钟独立显式推进；跨 Core 回合的快照跳转不隐含补发生产/维护。这验证迁移和连续账本，不证明正式 Core/后勤时钟已经耦合。全知确定性脚本仅是规则压力测试，不是公平 AI 平衡测试。

## 身份与总账

- 现存单位按 Core unit.id：保留库存、目标/上限、债务、影子 strength、attrition、优先级；更新格位、兵种、控制器、Core step。
- 增援用永久 Core reinforcement slot ID，初始影子库存 0，沿用原选定 2B/4B 上限。没有免费物资。开始新实验才按 EXP003 初始库存公式配置。
- Core 消灭：库存一次性进入 destroyed sink，注销 ID；再次处理同快照无操作，禁止向前序快照回退复活库存。
- 枢纽 ID、位置、库存、W/配额、目标与容量随片段延续。地图通行事实替换；实验铁路/桥容量保留，不能在状态切换时恢复默认值。
- 失联保留仓内库存，不能向不可达单位发货。Core 无实验枢纽所有权，control:null 不推断占仓/易手；敌占节点只阻断通行。本轮不新增自动缴获规则。
- 每次成功结算仍用原 epoch 去重；done 保留完整历史。迁移不改变 tick/epoch，也不重复结算；旧显示路径清空，历史账本只在全知视图中保留。
- 全局核对：初始库存 + 实际来源注入 = 单位及枢纽现存库存 + 累计维护 + Core 消灭库存损失。当前 EXP004 页面不执行影子 attack；若扩展行动消费入口，须同时扩展累计 action sink，不能直接调用旧 attack 后声称此审计已覆盖。

Q=4，即整数 1=0.25 SP。整数配送与 Fraction 债务沿用 EXP003。浮点仅用于耗时和 MILP 实现，整数解与约束独立复核。3 秒整次预算含双军、各级分配、IPC 和校验；失败不提交任何状态；进程终止清理可使响应墙钟略超过 3 秒。
