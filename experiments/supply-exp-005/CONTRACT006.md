# SUPPLY-EXP-006 · 玩家战后选择补充契约

继承 CONTRACT.md 的全部 EXP005 数值、求解器、时钟和三个起点；本文件仅覆盖自动战斗选择条款。Core TypeScript、RNG、地图、补给算法及实验容量不改。

- 每个用户 Action 是独立原子事务。宣战成功时扣一次攻击费用并保存 pending；双方随后按决策所有者逐步操作。已提交宣战不因后来另一个非法选择撤销；非法选择本身不得产生部分状态。
- 有选择的损失分配、撤退、推进、突破、重点突击、防守反应由玩家确认。Core 的确定性唯一损失可自动执行；无任何反应单位时自动 PASS_REACTION。其余不主动跳过。END_PHASE/END_SIDE 不得跨越 pending。
- 防御、强制撤退与损失分配额外0 SP（继承 EXP005）。推进、突破、PASS、防守反应新增 SP 费用为0（必要显式实验默认，不套用普通 MOVE 装甲费用）；防守反应原有 CP/资格照旧。
- 重点突击是新一次直接攻击：单个攻击者最多支付1 SP；同样使用实际支付和债务的较低攻击系数。宣战时锁定攻击系数，防守方选择期间不按已扣后的库存重算。重点突击仍受 Core 原资格限制，D≥2 不具备资格。
- 库存和债务仅按原时点更新。战后移动不触发配送，苏军完整回合结束才结算双方。未知通路不承诺配送；恢复片段仍为特殊容量，不推荐平衡数值。
- 每次操作校验当前 pending 决策方（可能不是 activeSide）。玩家 DTO 只给该决策方 pending、己方储备与选择字段；不返回权威路径候选、战斗上下文、隐藏敌情或 RNG。路径由玩家输入，权威拒绝泛化；合法性并不保证由客户端推算。
- 本地热座允许主动切换双方，研究回放仍是显式全知导出，不是多人身份鉴权。完整 EXP006 回放使用本分支；历史 EXP005 自动战斗回放使用固定 checkpoint 分支。
