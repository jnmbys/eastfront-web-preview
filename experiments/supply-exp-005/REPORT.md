## 已真实生效

Python 仍负责 EXP004 精确配送；本地服务以 JSON 调用隔离 Node Core。成功时一起提交 Core、物资、债务、epoch、请求 ID 和回放；不存在先扣资源再等另一个系统确认的持久中间状态。

- 装甲/摩托普通移动实际扣最多1 SP；直接攻击单位各实际扣最多1 SP。物资进入累计行动消费账。
- D≥2使真实普通移动总MP封顶1；超预算路径由引擎拒绝，包括公路加成，未给予地形/ZOC特权。
- 攻击强度按实际付款及债务的较差系数进入真实CRT结算。固定反例：G-I-02攻击I8，同一骰子 **5+1**，新补给攻击强度 **2**、最终列 **1:1**、结果 **AR**；旧补给强度 **4**、列 **2:1**、结果 **NE**。前后RNG状态一致，未改CRT/骰子。
- 回合末短缺损耗真实改变 Core step/alive，达阈值消灭并注销库存；重复请求不再扣一阶。
- 修路是实际 RAIL_REPAIR。修复 C10–D10 后当下库存/债务不变，完整回合末才配送。恢复例中 G-I-05等单位 D **2→1→0**；另一个分支在 D=1、库存已补充时完成真实再次攻击，攻击强度3。

新模式关闭旧半径快照写入、旧移动扣值/攻击倍数/OOS防御折半；资格标签来自新债务。旧模式不运行新结算、不扣新资源。原Core与隔离Core旧模式在接受和拒绝动作上的完整结果逐字相等，见 old-core-equality.json。

2. **断供后突围/救援**：从EXP004 T8起点真实等待三完整回合，T11自然形成债务；对比新/旧模式的1–2步候选与实际合法性。突围可能没有合法出口，不保证救援成功。
