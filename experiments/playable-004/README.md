# PLAYABLE-004 动态运输与维护取舍

基线：`1ac7e6c00af55dfab9a33896f3cef892a20c6cd3`。独立本机候选，无生产部署。

## 启动、访问、关闭与回退

在此仓库运行 `powershell -NoProfile -ExecutionPolicy Bypass -File experiments/playable-004/start.ps1`，访问 **http://127.0.0.1:4186/**。选择“新补给＋工业018 · 德军T5连续战役”，开始战役。不是公网地址。需要既有 Node 依赖及 Python/SciPy 1.17.0；启动脚本核验018原运行文件，不自行安装资源。

保持服务运行；关闭用 `powershell -NoProfile -ExecutionPolicy Bypass -File experiments/playable-004/stop.ps1`。本机仅一个内存实例；网页刷新后同模式可以重连，关闭服务会结束实例，尚无存档导入。候选验收临时使用4187，交付恢复同一4186入口。

回退：关闭004，在保留的 `playable-003-continuous-campaign` 目录运行 `experiments/playable-003/start.ps1`，恢复同一地址上的003新实例。没有改003原分支。004的 `experiment.json` 可关闭动态实验：关闭后仅跳过运输继续战役，不会自动恢复003固定牺牲方案；完整回退应使用003。

## 解除的限制

- 不再比较015保存方案的输入或旧检查点。每次使用当前授权地图、真实本方位置、库存、欠账、枢纽、公开铁路和共享容量重新构建原精确网络。
- 默认每个本方存活单位的维护不低于“保持当前安排”的基准。玩家可逐单位选择最多减少0至应付维护量的整数q，1q=0.25SP，并设置已有1–3配送优先级；未选择的单位不削减维护。已有库存仍先维护，不能凭选择把它扣留。
- 复用015完整网络、原实际维护状态建模及目标顺序，仅增加玩家维护底线。配送优先级只作用于原储备配送目标，不覆盖维护底线。不宣称全局最优。
- 物料合同仍是不可拆分的1P＋2E2整套。结果为0或1套，不能凭本轮将货物拆零。无容量与未在预算内求解分开显示。
- 确认会执行E8结束阶段、原SP结算与前送，同一次根状态原子发布。预览只读，不扣费、不变Core/RNG、不占容量。普通“结束阶段”明确表示不运输材料，仍可继续。

## 保留的实际限制

仍仅原T5真实起点，T5一次性10I装备预算与订单；2E2生产3I、交接2I、E5/E6加工；T7原后备池1P及独立2I；T8另付1I照管。没有持续工业收入或免费补仓。

材料仍限E8 A10→B10→C10铁路服务，GH2接收，T9可用，E9到期。共享负载为两铁路边各8q、运输工作16q、GH2处理8q。T9德国恢复阶段只对C10的G-I-01使用1P＋2E2原材料恢复，原资格、次数和唯一支付不变。目标离开、铁路不合格、照管或物料缺失属于服务失效，不能通过减维护绕过。没有异格末端配送或任意回合服务。

任意T1工业初始化、持续收入、更多工业对象/窗口、AI后勤策略仍缺。苏军AI保留原作战单步执行并承受真实新补给效果，双方后勤人工接管。35项未决没有被批量关闭。

## 授权信息和事务边界

`public_input` 删除敌方物流、真实隐藏占位/ZOC、历史账目与权威哈希，使用当时German PlayerView中的已识别单位和公开ZOC规则重建已知态势。未知通路保持条件性，不承诺安全。不会向策略传递全状态合法性答案。

预览返回的是授权条件下的方案，确认才检查原真实服务资格与整套网络流证据。任何受阻均整笔不变，不能自动改供给或接受新代价；每版本一次失败执行后禁止继续试探，普通行动不锁死。每版本最多12种选择，缓存相同选择；求解与提交分别3秒预算。预热不计入规划计时，超时未解不会伪装成无解。

计划令牌绑定当前版本，变更选择或实际动作后必须重新预览。沿用四字段请求和原回执查询：`operation=FREIGHT_<planId>`，同请求ID始终对应同计划；确认后读取失败保持锁定，恢复读取不会重复扣费。无公网检查点注入接口。
