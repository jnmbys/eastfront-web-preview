## 试玩

本候选入口 http://127.0.0.1:4222/ （仅本机）。进入现有暂停战役。

1. 选择己方部队；普通移动仍用现有持续推进命令，不增加“开始移动”。绿箭只表示权威已经接受的当前一格行军段，后续路径每步重评估。
2. 点击地图圆标，选择相邻合格部队，点正面攻击或支援攻击。蓝支援不自动跟进；红进攻在目标清空后转有耗时的正常推进。
3. 选军团突出宽半透明计划，选单位突出该队动作，选圆标突出该战斗来源。“突出全部行动箭头”是可选项。
4. 接管/暂停取消后续主动动作；正在遭到的敌军攻击不会冻结。暂停世界才停止模拟。退出前暂停、保存。

启动（服务已为本次交付启动并保留）：在本目录仓库根运行 `node ai/local/build.mjs`，随后 `node experiments/grand-map-r1/server.mjs 4222`。Windows 推荐下述脚本隐藏后台启动。
关闭：运行 `powershell -ExecutionPolicy Bypass -File experiments/grand-map-r1/stop.ps1`，仅核对并关闭4222上的本候选进程。先在网页保存，脚本不会自动保存或覆盖存档。
回退：原分支grand-map-001-control-battles及独立存档保留；启动其原服务后打开 http://127.0.0.1:4221/。最终复核时4221没有监听，本轮没有启动或修改它，不能保证此前内存进度仍存活。无需替换本候选存档。

独立存档：`%LOCALAPPDATA%/EastfrontSaves/grand-map-r1/campaign.json`，完整保存交战分组、命令、在途行军、RNG、账本与请求回执。新规则标记 `GRAND-MAP-R1`，拒绝未匹配版本；本轮不转换旧存档。加载默认暂停，原通信代次隔离旧请求。

## 明确规则与限制

- 支援是当前实验的真实 DIRECT/SUPPORT 命令：己方存活地面作战单位、相邻1格、组织度至少45、库存至少1q、正火力、公开可通行边、目标有已识别敌军且已有持续交战。HQ/运输不能参与。没有多格间接火力。
- 每步用授权 PlayerView 再核验；不合格停止主动出击，不反复提交。不增加伤害倍率；沿用原逐单位对伤害、反击、组织度、补给支付与撤退。原单位对模型中多个接触分别结算的行为未改；显示合组不复制结算。
- 支援目标交战脱离或本部撤退后转暂停直属HOLD；保留损失，不恢复次数，不自动前进。攻击清空指定目标后仅转正常ADVANCE，不瞬移。
- 同一实际接触地块的单位对归入稳定 engagement ID；参与者去重，记录原pair IDs。不同地块不因屏距聚合。脱离后结束，后续重新接触获得新ID；结束即移出地图、留战报。
- 不展示敌军精确人员/组织/装备/库存。圆标仅描述己方当前承受情况：平均组织<35或单步组织平均下降>12为“己方承压”；至少2步、平均组织≥60、单步平均下降≤5且本步总人员损失<8为“己方暂能维持”；其余中性。面板给出实际本方变化和不确定性；这不是胜率或整体优劣证明。
- 绿箭实线路径、红箭交叉符、蓝箭加号、灰色虚线撤回；同起终点的攻击/支援仅中段并列，真实端点不变。自动瞬时撤退已完成后不伪造在途箭头，仍通过报告/交战状态表达。
- 全部来源仍逐单位可追溯。圆标避让单位命中区，静态地形/CITY宿主不重建。近距离多个真实目标分别偏移和引线，不合成虚假统一战况。
- 仅德军玩家、苏军AI的既有短战役。支援命令由玩家明确下达；未增加军官自动支援策略。用户视觉与趣味性尚未验收。
