## 结算投影与证据

在原`clock=full`下，按原结算算式只读计算：实付＝min（应付，期初库存＋配送）；库存＝期初库存＋配送−实付；足额时D减1至不低于0，否则D按未付比例增加、最高3；仅D＝3且未付时增加耗损累积，再按整数部分投影掉步。先用同一算式核对008保存的真实原结果，再计算候选。

本轮新增维护缺口是真实的候选代价，不能用“库存未降”掩盖。D＝1是原规则门槛，但没有在这里执行作战；库存约束也可能影响攻击，因此不将该门槛直接换算为攻击损失、未来掉步、存活回合或VP。

`VERIFICATION.json`记录12组检查通过，包括：完整16目标阶段、213变量及360约束逐系数复核、四项预留与全部流量/来源/仓容限制、60单位原公式投影、完整苏方冻结、相同唯一候选复跑及输入不变。每个非恒定优化阶段均返回最优状态；恒定阶段按原逻辑跳过。最终保存的求解与复跑耗时分别见`RESULT.json.seconds`和`VERIFICATION.json.rerunSeconds`，均须低于3秒。
