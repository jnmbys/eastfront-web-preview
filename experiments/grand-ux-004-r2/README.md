# GRAND-UX-004-R2

基于运行 2d318464 / 证据 40f625c0。此分支只改手动指挥、地图摇杆和实际定位到的性能问题；固定格位、同格堆叠、战线、领土布局、战斗与经济结算保留。

## 操作

- 选任意己方单位，点空地直接移动；点已识别敌军提交攻击。支援／撤回先选工具再点目标。普通动作没有第三次确认。
- 点友军格出现就近“选择该队／移动到此格”，该选择直接执行意图。拖动、双指及超过500ms的长按抬手不下令。
- 手动动作保留军团成员关系。有限命令到达目标／支援结束后恢复军团计划；停止驻守持续到点击“恢复军团计划”。停止不会取消已发生战果、免除敌方攻击或跳过耗时撤出。
- 设置／读档内开启摇杆，选左右手和速度。触控设备默认显示，设置只在本浏览器保存。松手、离开、取消、失焦归零；不改变缩放，不发送游戏事务。

## 修改与验证

1. 手动命令覆盖层 `MANUAL-INTENT-1` 保存在原单位状态中；仍经原实例、代次、幂等、当前合法性校验。保留已接受的耗时撤出。旧存档不重分配部队／领土，未知覆盖层版本拒绝读取。
2. 授权视图合并仍逐包执行；同帧显示合并沿用原调度。操作面板保留DOM及展开状态，只换变化内容；事件绑定替换旧闭包，避免推送后一次点击触发多次提交。关闭的城市／设置不再生成整个大型面板。
3. 同一个权威步、同一报告阶段复用各方授权视图，避免每场接触重复克隆1280格。识别格查询改Set。缓存不跨阶段、不跨步，没有放宽授权。
4. 地图待确认箭头明确标作“目标意图”，不伪称已接受路径；原真实行军箭身进度保留。

`check.mjs`：120步无新手动命令时，双方授权视图、权威状态、经济、战斗报告、RNG一致；完成后归队、持续驻守、军团改令优先级、耗时撤出、存档版本、敌方权限。

`dom-check.mjs`：100次显示更新后同一按钮只执行一次最新处理，展开状态保留（合成DOM测试，不是真机）。

## 性能与局限

固定正常起点100步、同机同输入：模拟平均104.1→76.0ms（约27%下降），最大237.3→113.6ms；快照18.9→20.0ms，差量4.5→4.8ms，压缩0.28→0.28ms。这是离线测量，不是公网/平板帧率。

最终浏览器窗口：1×74.4秒、4×63.7秒、暂停59.8秒。长任务分别5/14/0次，最大92/91/0ms。所有窗口拖动缩放比例保持1.4。rAF仍有约1秒间隔，不能据此宣称平板卡顿解决；其间没有对应1秒长任务，后台调度/工具观察也可能影响，未作确定归因。原始数据与限制见performance-summary和压缩轨迹。

上线前旧版本独立公网访客，暂停/1×/4×各60秒；4×时Render CPU约0.47核/0.5核，内存98MB，暂停回执曾4.04秒。服务端有CPU压力，不是内存不足；本轮不升档。该探针最后重连断言超时，已保留原失败；网页本机重连通过，发布后仍需单独记录公网复核，不能混用。

未验证华为/iPad真机与原生双指。工具不支持原生双指注入；没有邀请用户重复采样，也没有把合成事件列为真机通过。4×仍比1×负担高。无服务器费用变化。
