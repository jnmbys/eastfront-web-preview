# FLOW-001 可运行流程试验

独立分支：`flow-001-phase-streamlining`。保留原地图、美术、规则和 Core；不合并、不部署。此交付采用用户允许的保守方案：**空恢复自动准备 + 连续整备入口**，没有跨阶段一键计划。

## 启动、关闭与回退

需要 Node.js（本次使用 24.19.0），无需安装运行依赖。从仓库根目录执行：

```powershell
node experiments/flow-001/serve.mjs 4180
```

或运行本目录 `Start-Flow.ps1`。启动时逐文件验证固定 Core 的 SHA256，不匹配即拒绝启动。仅监听 `127.0.0.1`，保留本机 Host/Origin 限制，仅提供静态 GET/HEAD，没有新增业务 HTTP 接口。

- 正常部署、试验入口：`http://127.0.0.1:4180/?flow001=1`
- 可立即操作的对照起点：`http://127.0.0.1:4180/?flow001=1&flowFixture=1`
- 相同起点的原界面：`http://127.0.0.1:4180/?flowFixture=1`
- 完全原入口：`http://127.0.0.1:4180/`

点击“新游戏”进入。对照入口按种子 17001 通过原 Core 的合法部署动作放置双方 58 个单位，起于 T1 德军补给／铁路。没有修改单位、补给或资源来构造这一主对照。

试验的“自动通过空阶段”对每个控制者默认关闭；双方需分别主动勾选。可随时取消勾选，立即停止尚未提交的自动准备，已生效动作不撤销。取消勾选即可在当前局面恢复手动阶段确认。去除 `flow001=1` 恢复原版布局，但重新加载会像原本机界面一样丢失当前内存对局；本试验没有新增存档。

关闭：在启动终端按 **Ctrl+C**。本次验证用的服务器及浏览器均在交付前关闭。

## 如何操作整备

1. 到恢复阶段，在地图选中己方受损单位，查看原界面的恢复资格、剩余 RP、恢复上限及单次费用，逐项确认恢复。
2. 点击“完成恢复，继续筑垒”。若已开启空恢复自动准备且己方存活单位均无步损，只提交本人 READY。
3. 筑垒阶段仍在同一操作区；选中单位后按当前权威状态重新校验，再确认筑垒。此前不会提前筑垒。
4. 点击“完成整备”，后续阶段和换边隐私交接仍由原流程处理。

界面没有承诺跨阶段原子性。没有预收费用或排队恢复计划；已有动作不回滚。单阶段操作绑定状态版本、控制者、选择及开关代次，旧命令停止。任一恢复／筑垒／准备动作失败，关闭自动准备并停下，不自动重试支付。原命令反馈及单位实际状态表示已完成部分，未提交的动作不会执行。

## 哪些确认会减少

只处理固定本机 Core 的空恢复：使用原授权投影内完整的己方存活单位步损；任一己方受损单位（包括队友单位）都保留手动选择。**不扫描所有单位的恢复合法性，不利用隐藏敌军判断是否可恢复。** 没有选中单位不是“空”。本机投影同步完整；网络投影、查询未完成、待决状态、未知扩展、其他规则版本或观察者模式均不自动提交。

移动、战斗、铁路、补给、增援、筑垒、工业选择都不自动通过。未知工业扩展直接停止，未支持照管、运输或到期隔离自动决策。只有原 READY 动作，没有 END_TURN 捷径；不替队友准备，原全部控制者屏障与隐私遮挡保留。

本轮没有支持联机自动化，没有改 ACK／权威状态、查询或合法选项门禁。合成多控制者检查通过不等于真实多人验收。

## 实际对照结果

同一种子、真实 640 格地图、58 单位合法部署；T1 德军补给／铁路 → 德军全部阶段 → 苏军全部阶段 → T2 德军补给／铁路。双方各选择一次一步移动及一次不同单位筑垒，业务选择完全相同。两份独立浏览器对局用原地图操作完成，再与规则层复跑逐字段比较。

| 指标 | 原流程 | 精简流程 |
|---|---:|---:|
| 人工结束阶段确认 | 10 | 8 |
| 自动提交本人 READY | 0 | 2 |
| 业务选择（2 移动 + 2 筑垒） | 4 | 4 |
| Core 动作（不含相同的部署） | 14 | 14 |
| 换边隐私确认 | 2 | 2 |
| 业务网络请求 | 0 | 0 |
| 首次开启选项 | 0 | 2 |

**少 2 次阶段确认，不是少执行 2 条规则。** 首轮分别开启双方选项还需额外 2 次勾选，因此这次单回合演示的首次设置会抵消总操作数节省；选项保持开启后，后续符合条件的空恢复才持续少确认。本结果不代表网络更快。地图选择、路径选择和新游戏等相同交互未算作“结束阶段确认”。

完整 GameState（包括所有单位、资源、动作日志、ID 计数器、增援相关记录、胜负和 RNG）逐字段一致。终态 SHA256：
`0f1dc6a20a834913bf7f1d8af87ff038ad8f90baadab330f28126757d0c980c4`

终态 RP 德 8／苏 12；CP 德 3／苏 2；恢复 0 次，增援部署 0 次；胜负未决；RNG seed/state 17001，draws 0。主对照没有进行战斗、恢复支付或强制增援部署；这些不能从空恢复对照推导为完整规则验收。
