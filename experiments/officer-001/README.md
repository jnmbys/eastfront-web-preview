# OFFICER-001 · 军官委托候选

基于 PLAYABLE-004 `b7f5644c619c461e2f2d2a3d642670b572913d65`；独立分支 `officer-001-delegated-command`。未合并、未部署。资料辅助手写策略，不是训练模型，也不声称胜率或战役能力已提高。

## 试玩与关闭

在仓库根目录运行 `powershell -ExecutionPolicy Bypass -File experiments/officer-001/start.ps1`，使用现有 Python/SciPy 1.17.0 环境，不自动安装依赖。访问 http://127.0.0.1:4186/ ，选择“新补给＋工业018 · 德军T5连续战役”，再开始战役。本地地址，不能从其他电脑访问。

停止：另一个终端运行 `powershell -ExecutionPolicy Bypass -File experiments/officer-001/stop.ps1`。关闭服务会结束内存对局；没有存盘功能。刷新后重新选相同新补给模式可重连同一实例，军官、命令、性格和已执行动作保持；退出再进入不会创建新工业实例。需要新局时重启服务。

回退：先停止本候选，再到原 `playable-004-dynamic-logistics` 工作目录运行其 `experiments/playable-004/start.ps1`。004原分支和源码未修改；回退不迁移本候选内存局。军官模式也可在当前局直接关闭，所有部队交回人工，不撤销真实动作。

## 操作

1. 默认全部直属。开启“军官委托”，选择原创军官和单位，点击“交给此军官”。可逐个加入；转交时先移除旧归属。
2. 进攻或守备：点击“在地图选择命令目标”，复用COMMAND的地图标记，再明确“确认下令并执行”。普通COMMAND标记本身没有执行授权。守备第一版为一个位置及其邻域，未做多边形区域编辑。
3. 整补不需要目标。恢复默认额度0；分配现有RP后才可能恢复。额度是自动使用上限，不是额外资源，也不是阻止玩家花费的托管。调度时再次取当前可用RP最小值；所有真实行动串行由Core裁决。
4. 命令跨阶段、跨回合保留。军官在当前阶段连续操作所属单位；无行动后停止等待。玩家仍决定何时结束全军阶段。可修改、暂停、取消；“调回直属”立即撤销该单位自动权限。
5. 暂停先停止新调度，已经提交的动作等明确结果后交还。待决不清空、行动次数不恢复。跨编组联合行动先暂停相关军官，由玩家提交。真实任务记录与COMMAND虚线计划分开。

军官只接入现有**德军T5新补给模式**；旧规则T1双方人机入口原样保留，未接入军官。三名军官使用稳定的四维不同取舍：出击意愿、损伤容忍、缺供谨慎和集中偏好；内部数值/类型不在玩家界面显示。源码可审计，不承诺阻止查看本地源码。

## 实际支持与人工边界

支持本组移动、目标邻域内攻击、可归属单一编组的损失/撤退/推进等战后选择、原RP恢复和筑垒。保留014推进保护和原路径预算/邻敌停步。军官发起战斗时统一调度原苏军AI处理敌方反应；混合编组或无法归属的全局待决停给玩家。每次真实行动后重读公平视图；一次Core拒绝即暂停，不反复试探隐藏因素。

铁路、部署/增援、HQ/炮兵反应、跨编组联合攻击、全军阶段结束、工业订单、维护削减、运输确认和材料恢复仍由玩家处理。苏军普通回合仍沿004单步AI入口；不新增AI后勤。后勤需求只报告己方受损和缺供，不替玩家花工业预算或削减其他编组维护。

004原服务限制不变：同一T5起点，一次订单、T7人员、T8照管/E8动态前送、T9指定单位地点的材料恢复；任意T1工业初始化、持续工业收入仍未实现。新委托不绕过新补给效果，不改变价格、RNG、Core或结算器。
