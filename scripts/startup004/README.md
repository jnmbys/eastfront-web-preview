# STARTUP-004 independent device session

Run from the `startup-004-device-acceptance` worktree. This harness uses the frozen R1 archive; it does not rebuild or edit game code. The owner gate is the existing `scripts/mp011-r1/owner-preview.mjs`. Only STARTUP-004 owns ports 4290/4291/4292 and its newly spawned tunnel process.

1. `powershell -NoProfile -File scripts/startup004/prepare.ps1` extracts a **new** candidate directory only after the archive SHA256 and entry paths pass. If already present, run `node --input-type=module -e 'import {verify} from "./scripts/startup004/integrity.mjs"; console.log(verify())'`. The archive remains in the prior R1 worktree; its manifest remains in `evidence/startup-003-r1/candidate-manifest.json`.
2. `node scripts/startup004/server.mjs` starts loopback services. It refuses a different pinned tunnel executable or candidate file hash. Do not reuse another task's server/tunnel. The 90 minute maximum lifetime is a safety cap, not a benchmark setting.
3. Inspect `local-check.mjs` and `aux-check.mjs` for the recorded desktop procedure. They require the installed Edge and Playwright paths specified there. They write evidence: use a fresh evidence destination for a subsequent run, preserving the original evidence. Desktop checks include 380 HTTP byte comparisons, authentication boundary, default/serial, actual LOD switching, a saved/downloaded JSON check, terrain PNG saving, and a local synthetic map-fetch failure. These are not Huawei observations.
4. After local checks, the owner enters their retained temporary password into **loopback** `http://127.0.0.1:4292/`. Never put the password in scripts, chat, evidence or command arguments. The server opens its own temporary HTTPS and then the authenticated upstream gate. Run `node scripts/startup004/probe-public.mjs` before sharing the origin from `.startup004/run/state.json`.
5. On Huawei, open a fresh page at that origin. Record device/browser, network and actual cache condition. Start default once. Observe completeness, drag, zoom, and far/medium/close. Landscape and collapsing the native game side panel may be needed to reach close LOD. Do not mark an unreachable LOD as passed. Save terrain PNGs where useful, then JSON. A server receipt SHA256 must match the browser JSON. A text backup is optional.
6. Review each JSON with `node scripts/startup004/review-record.mjs evidence/startup-004/records/<id>.json [new-summary.json]`. Check `kind`, actual UA, user observations, mounted LODs, outcome, counters and receipt. `kind=device` means it arrived through the authenticated public origin; it does not identify hardware by itself. Do not rely on the desktop zero-pixel-difference result from R1 to approve hardware.
7. Only after successful default observation and saved/verified evidence, POST `/serial-enable` on loopback 4292 with Origin `http://127.0.0.1:4292`. Give the owner a **new page** at `/?terrainLoad=serial`, recording that the previous default run may have warmed cache. Candidate resources are exactly the same R1 files. On any failure, preserve the JSON and stop; do not automatically refresh, retry or continue to serial. A saved device failure automatically closes this session.
8. `node scripts/startup004/close.mjs` closes only this session and separately records process, listener and actual public HTTPS checks. Network/DNS/TLS failure is classified unknown, never silently counted as public closure. Preserve `.startup004/run/state.json` and redacted/safe metadata as evidence after closing.

The observer calls the original startup-complete callback before observing its event. It does not patch loading, decoding, drawing, readiness decisions, or the image fallback paths. DOM-ready and available DOM controls are separate from visible paint and actual touch input. The recorded first terrain completion is useful as a startup milestone. Later LOD completion includes the human delay before zooming and is **not** startup latency. Diagnostic snapshots add observation overhead. Native image records remain bounded to the last 12; Resource Timing is not an independent decode-CPU measurement or proof of cold cache. No production multiplayer service is started or configured.

The tracked evidence directory includes both desktop calibration and device records, separated by filenames and receipt kind. Failed preflight evidence is retained. New sessions must use new evidence names/directories and preserve the original frozen harness and records.
