# ART-SCALE-018｜地图规模约束研究

日期：2026-10-02（北京时间）。源码基线：
`754da7cdfb7a343f51d7a008cec921c4dbd9d0fa`（ART-EXPANSION-017）。

**建议以640格继续工业设计，把640–800格作为规划区间；800格是有条件的研究上限，
目前不建议采用1000格。** 现有五图集足以保持视觉方向，扩图收益必须来自战略设计，
不能只为给工业“腾空间”。增加格数不会增大单格，AC10和017的BN36问题仍会存在。
本研究没有创建800/1000格地图，没有改正式640格、规则或渲染器，也没有部署。

## 比较口径

- 017保留的015全图记录提供可比的640格基线：77个运行文件、3,996,913字节，
  4096×3689主画布、2457个DOM元素、58枚展示单位。017的60格样片不能当作全图基线。
- B/C假设格距仍为HEX_SIZE=42、有效长宽比与当前相同、地形/河路密度相近，五图集
  和代码不变。只按面积比例推算外包矩形与资源量，不指定新的行列数、坐标或地形。
- 所有包体为未压缩字节，MB=1,000,000字节。B/C数据均为模型估算，无首屏/帧率实测。
- 58枚单位是美术夹具，**不是将来的兵力上限**；分别比较固定58枚与保持当前平均密度。
- 工业数量与表示方式未定，工业增量单列；不把未制作的工厂体系算作免费或已完成。

## 素材复用的边界

015/017的城镇U/L/双院落组合、邻接林缘、山脚土色、接触阴影、真实边生成的河岸与
桥点可以继续使用。017已经证明不同原点及32/60/108格输入可运行布局；只有60格做了
实机检查，不能据此宣称800或1000格实机通过。

现有位置公式经模2/3/4选择，同类邻接平移12列会重复；山脊轮廓和通用河岸折线
在500%可见。优先确定稳定美术ID/种子、组合和邻接契约，而非直接增加图片。
五图集能供应地貌与普通屋顶，尚不能证明工厂、仓库、站场在中景可清晰区分。
017只验证了虚线框占位，工业标识仍待设计。

工业素材成本独立于格数：共享图集被画F次不需要下载F份，但合成工作会增加。
未来图集的下载增量必须以实际压缩文件计量；解码RGBA按 `宽×高×4`，例如单张
1024²约4.19MB（仅内存算例，不是批准制作规格）。Canvas内烘焙可不增DOM；017式
无交互SVG候选框每处3个节点，另有共享容器。交互菜单、标签和状态图标需另外预算。

## 工业设施：净空、铁路、操作空间

所有尺寸均为当前渲染世界单位，不是米，也不是规则尺寸。

| 部分 | 已有约束/本研究建议 | 含义 |
| --- | --- | --- |
| 六边形 | 外包约72.75×84，面积约4583 | 扩格数不改变该单格空间 |
| 单位净空 | 中心68×68 | 来源于现有美术遮罩；保留选择与堆叠操作空间，不等同触控像素 |
| 标签 | 20×10，中心下方y=29 | 工业屋顶/阴影不能据此遮住原标签 |
| 铁路/道路 | 中心线两侧各7（5+2净空） | 由现有布局排除带得出，不是铁路最终宽度标准 |
| 工业占位内容 | 017曾用38×20 | 仅验证过候选框，**不是已确认的设施最小尺寸** |
| 初步研究净空 | 38×20内容加每侧2缓冲，即42×24 | 临时设计预算，需真实设施、阴影、标识确认 |

对单格进行0.5世界单位步长的矩形容纳检查（不是新地图或实机图）：

- 无单位的空格可容纳38×20或42×24，同时避让标签。
- 横向铁路穿格中心时，38×20仅剩一条狭窄可摆范围；加入每侧2缓冲后，42×24
  在该几何场景中无解。不能把“38×20框曾放得下”直接等同“工厂成品放得下”。
- 若同格中心保留68×68单位净空，两种矩形均无解。单格外包宽高也能证明这一点：
  工业矩形要避开单位就必须完全置于单位框的一侧，但两侧剩余空间不足。
- 这是轴对齐工业矩形、中心直铁路和固定标签的特定检查，不能推广为所有铁路角度、
  河岸或桥头都无解；真实布局仍需逐格检查。清晰度、手指操作和阴影不由几何检查验收。

建议先把工业群作为**2–3格的视觉规划单元**研究：设施核心与站场/交通尽量分担，
需要集结空间时另留单位操作格。这是留白预算，不是新增“工业地形”或强制占格规则；
小仓库能否与交通共格、单位进入后设施是否降级显示，仍需产品/规则共同决定。
铁路必须读取真实连接、桥梁与通行状态；不因为画了站场就添支线或视为已接通。
应预留“轨道方向/入口、设施边界、标签、单位覆盖策略”接口，不决定真实地图地址。

为了直观看空间比例，若仅作算例设8个工业群，每群留2–3格，共16–24格：

| 场景 | 视觉规划空间占全图 |
| --- | ---: |
| 640格 | 2.5%–3.75% |
| 800格 | 2.0%–3.0% |
| 1000格 | 1.6%–2.4% |

8个群不是需求预测，格数也未从正式地图划走。数量固定时，这个差距不足以单独
证明必须扩到1000格；若工业群和单位随面积同步增加，扩图也不会缓解局部拥挤。

## 移动端风险与推荐门槛

1. **内存/纹理**：维持清晰度时B/C列明画布预算已达约83/102MB，再加解码和浏览器
   副本可能形成更高峰值；维持4096上限则主要损失细节。分块缓存、驻留上限及低清晰度
   层级尚未实现，不能提前将其效果计入表格。
2. **操作与辨识**：假设可用地图区域为360×600 CSS像素，按全图适配、300%缩放，
   单枚47.88世界单位宽的单位牌投影约为20.8/18.6/16.6px。若把44px作为操作预算，
   三方案约需6.35×/7.10×/7.94×，C已接近当前8×上限。44px这里只是预算假设，
   不是手机验收结论；实际侧栏、屏幕方向、命中区与最大堆叠会改变结果。
3. **CPU/DOM**：画布尺寸封顶不代表布局成本封顶。当前worldContext逐格筛连接，
   裁剪/贴片会扫描连接和单位；同密度下某些全量扫描工作随N²增长，B/C约为A的
   1.56/2.44倍。DOM仍保留离屏格与单位，选择还会重建单位层。这些是工作量推导，
   不能换算成启动毫秒或帧率。

**A：当前推荐。** 先明确距离/时间尺度和工业群数量，验证2–3格视觉规划是否满足玩法。
AC10的共格辨识问题仍需独立解决；640也尚未通过移动端性能验收。

**B：条件备选。** 只有战略范围确需增加，并已确定工业/单位密度后才考虑。进入实现前
应冻结尺寸与连接契约；以目标移动设备检查常用缩放、最大堆叠、工业遮挡、冷启动和内存。
同时决定接受细节下降，还是先实现有上限的分块/可见范围方案。此处不承诺性能通过。

**C：暂不推荐。** 包体不是首要障碍，但单画布清晰度、单位操作和全量扫描的风险叠加。
在设备预算与渲染组织未确定前采用1000格，更容易引发美术尺寸、标签和工业布局返工。

启动、GPU、华为及物理触控均未验，历史708ms问题保留。本轮不尝试测量，不回填017
本地样片或016线上待验项，不提供假想扩图截图。
